## Скилл: Разработка Фичи (OpenSpec + Superpowers + Caveman)

### Контекст проекта

* Стек: **Python 3.9+**.
* Тесты: **Pytest**.

### Инструкции по этапам

### Этап 1: Проектирование (OpenSpec)

1. **Код не писать**. Изоляцию не включать.
2. Выполнить команду `/opsx:propose` (`/opsx-propose`). Создать файл в `openspec/proposals/`.
3. Описать в файле: суть, изменяемые файлы (включая `test_*.py`) и Критерии Приемки (AC).
4. **Caveman-ответ**: Показать путь к файлу спеки и спросить апрув. Без лишних слов.

### Этап 2: Изоляция и План (Superpowers)

1. После апрува использовать скилл Superpowers для создания новой git-ветки.
2. Использовать навык `writing-plans`. Перенести AC из OpenSpec в чек-лист `openspec/tasks.md`.

### Этап 3: Цикл TDD (Pytest)

Для каждой задачи из `openspec/tasks.md`:

1. Написать падающий тест в `tests/unit/test_*.py` или `tests/e2e/test_*.py`.
2. Написать минимальный Python-код для прохождения теста.
3. Запустить `pytest`.
4. **Caveman-коммуникация**: Не объяснять код. Писать только статус.
*Пример: "Тест упал: Ошибка X. Исправил. Pytest: OK."*

### Этап 4: Фиксация (OpenSpec Archival)

1. Запустить финальный `pytest` для всего проекта.
2. Выполнить команду `/opsx:archive` (`/opsx-archive`) для переноса спеки в историю.
3. Слить ветку в `main`.

### Ограничение Caveman (Глобально)

* Экономия токенов. Короткие фразы. **Главные действия жирным**.
* Никакой вежливости, приветствий и итоговых выводов.
* Текстовый ответ — максимум 2 строки (кроме блоков кода/markdown).
