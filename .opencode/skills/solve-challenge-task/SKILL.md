# Задание дня челленджа: код + видео + материалы для сдачи

Сдача = **обе** части: тег релиза с кодом и запись экрана. Нет любой части — задание не сдано.

## Границы

- Пишем только в текущий проект. Челлендж-репозиторий — только чтение; его README правит пользователь, агент готовит фрагмент.
- Любая мутация git (коммит, мерж, тег, пуш) — только после явного «да» на показанные `git status` / `git diff --stat` / список коммитов. Слияние — только fast-forward (`git rebase main`, затем `git merge --ff-only`); merge-коммиты запрещены. Создание ветки подтверждения не требует.
- `videos/` в `.gitignore`; видео, кадры и черновики README не коммитятся.
- Стиль — caveman: строки статуса, главное жирным. Без жаргона и англицизмов: «подтвердить (approve)», не «апрув».
- Два неудачных подхода подряд в любой фазе — назад к плану с описанием блокера, не третья попытка того же.

Скрипт записи: `$SKILL/scripts/record_screen.sh`, где `$SKILL` — каталог этого файла (`.claude/skills/solve-challenge-task/`; в OpenCode — `.opencode/skills/solve-challenge-task/`). В корне проекта `scripts/` нет.

## Фаза 0 — разбор и план

1. Разобрать задачу:

   ```
   ЧТО:       <своими словами, 1–3 строки>
   РЕЗУЛЬТАТ: <пункты «что считается выполненным», из текста задачи>
   ФОРМАТ:    <по умолчанию «Видео + Код»>
   ДЕНЬ:      weekN/dayMM   (две цифры: day06, day10)
   ```

   Если `ai-advent-challenge-9/weekN/dayMM/README.md` уже содержит раздел «Решение» со ссылками — день сдан, спросить, какой день имеется в виду. Сданный README не перезаписывается никогда.
2. Прочитать `CLAUDE.md` / `README.md` проекта — архитектурные ограничения обязательны. Проверить среду: `pytest -q` зелёный (падает до правок — сообщить и остановиться); `$SKILL/scripts/record_screen.sh doctor`; при необходимости LLM — файл `.env` есть (значение не печатать); `openspec/changes/` без незаархивированных изменений (есть — сообщить).
3. План решения: 3–7 пунктов — модули/команды/экраны, что нового, какие тесты доказывают каждый пункт РЕЗУЛЬТАТ.
4. Сценарий демо (управляет тем, что строим):

   ```
   СЦЕНАРИЙ ДЕМО (dayMM, 30–600 сек):
   1. <исходное состояние на экране>
   2. <ключевое действие>            # ≥ половины времени
   3. <результат на экране>          # доказательство каждого пункта РЕЗУЛЬТАТ
   ```

   Пункт РЕЗУЛЬТАТ, не видимый в сценарии, = сценарий неполный.
5. Тег: последний `git tag -l | sort -V | tail -1` плюс 0.1 (`v0.10` → `v0.11`).

**Стоп A**: поля + статус среды + план + сценарий + тег одним сообщением. Дальше — только после «да».

## Фаза 1 — код

**ОБЯЗАТЕЛЬНЫЙ САБСКИЛЛ:** `feature-builder` (инструмент Skill), весь его цикл без пропусков. Дополнения челленджа:

- `<change-id>` — из задачи (`add-export-command`); критерии приёмки в `proposal.md` — дословно пункты РЕЗУЛЬТАТ плюс шаги сценария демо.
- После ff-слияния — тег: показать `vX.Y`, дождаться «да», затем `git tag vX.Y && git push origin main --tags`. Релиз в GitHub из тега пользователь создаёт руками — напомнить.

**Стоп B** (итоговый статус после тега, ожидания не требует): `код готов: pytest OK, main = <sha>, тег vX.Y запушен`. Видео снимается только с слитого кода.

## Фаза 2 — видео

1. Подготовка кадра: терминал на весь экран; уведомления выключены; микрофон выключен; `.env`, ключи, личные файлы и лишние окна вне экрана; `history.json` со старым диалогом убрать (`mv history.json history.json.bak` или `/clear` в сценарии) — иначе в кадре чужие реплики.
2. Сухой прогон сценария без записи, с замером времени. Не проходит — чинить код или сценарий, не «снимать как есть».
3. **Стоп C**: «экран готов?» — запись захватывает весь экран пользователя.
4. Запись:

   ```bash
   $SKILL/scripts/record_screen.sh start videos/dayMM-demo   # расширение добавит скрипт
   # ... сценарий, без спешки ...
   $SKILL/scripts/record_screen.sh stop
   ```

5. Проверка (каждая запись):

   ```bash
   ffprobe -v error -show_entries format=duration -of csv=p=0 videos/dayMM-demo.<ext>
   ffmpeg -y -v error -ss 3 -i videos/dayMM-demo.<ext> -frames:v 1 videos/frame.png && stat -f %z videos/frame.png
   ```

   Длительность 30–600 сек; кадр на 3-й секунде не чёрный — PNG больше 10 000 байт. Чёрный кадр на macOS = у терминала нет разрешения «Запись экрана» (Системные настройки → Конфиденциальность) — выдать и переснять. Файл больше 150 МБ — пережать: `ffmpeg -i in.<ext> -vcodec libx264 -crf 28 out.mp4`.
6. Запись невозможна (нет рекордера, захват падает, нет разрешения) — две попытки, затем шаг пропускается: видео становится ручным шагом пользователя в Фазе 3, всё остальное сдаётся штатно. Подмена записи скриншотами, слайдами или роликом, собранным из вывода программы, — не запись экрана и не сдача.

**Стоп D** (статус; `history.json.bak` вернуть на место): `видео: videos/dayMM-demo.<ext>, N сек, кадр K байт` — или честный блокер.

## Фаза 3 — сдача

1. Черновик `videos/dayMM-README-draft.md` по формату челлендж-репозитория (образец: `week2/day09/README.md`):

   ```markdown
   # День M. <Название>

   ## Задача

   <текст задачи как пришёл>

   ## Решение

   Код: https://github.com/ivanshchitov/tabletop-ai-assistant-tui/releases/tag/vX.Y

   Видео: <после загрузки — ссылка>

   ### Как это работает

   - <2–5 пунктов: что реализовано, как проверить>
   ```

   Плюс строка таблицы недели (`weekN/README.md`):
   `| [MM](dayMM/README.md) | [<Название>](dayMM/README.md) | [Tabletop AI Assistant TUI vX.Y](<ссылка на релиз>) | [🎬](<ссылка на видео>) |`
2. Передать пользователю списком: тег и ссылку на релиз; путь к видео и черновику; ручные шаги — загрузить видео, вставить ссылки в `dayMM/README.md` челлендж-репозитория, добавить строку таблицы недели, создать релиз в GitHub.

## Красные флаги — стоп

- «Запишу сразу, сухой прогон потом» — без прогона переснимать.
- «Чёрный кадр, но на другом плеере видно» — брак, переснять.
- «Рекордера нет — соберу ролик из кадров/скриншотов» — не запись; честный блокер.
- «Пользователь торопит — пропущу подтверждение» — быстрота = короткие статусы, не пропуск стопов.
- «Тесты зелёные — закоммичу и залью сам» — только после «да».

## `scripts/record_screen.sh`

- `doctor` — платформа, рекордеры, вердикт «ГОТОВ / НЕ ГОТОВ» с подсказкой установки; на macOS дополнительно снимает 2-секундную пробу в `$TMPDIR` и проверяет кадр (ловит отсутствие разрешения «Запись экрана»). Ничего не пишет вне `$TMPDIR`.
- `start <basename>` — запись в `<basename>.<ext>` (`.mp4` ffmpeg, `.mkv` wf-recorder, `.mov` screencapture), PID-файл, жёсткий лимит 10 минут.
- `stop` — SIGINT, ожидание до 15 сек (файл финализируется), размер файла; `kill -9` только по таймауту.

Выбор рекордера: macOS — `ffmpeg avfoundation`, иначе `screencapture -V`; Linux Wayland — `wf-recorder`, иначе `gpu-screen-recorder`; Linux X11 — `ffmpeg x11grab`. x11grab под Wayland даёт чёрный кадр — `doctor` об этом скажет.
