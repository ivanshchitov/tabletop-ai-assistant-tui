# Приватный сервис локальной LLM — день 30

Сервис запускается отдельно от TUI: HTTP-шлюз проверяет ключ и ограничения, а одиночный
llama-server выполняет запросы Qwen3.5-2B Q4_K_M. Диалог хранит клиент и передаёт его в
`messages`. Закрытие клиента не останавливает сервис.

## Запуск на домашнем сервере

Нужны зависимости проекта, `llama-server` на PATH и GGUF модели. Профиль проверяется с
llama.cpp 0.5.0, build 11146, commit `7fe450e19`. Требуются `/apply-template`, `/tokenize`
и `/v1/chat/completions`; версия и доступные параметры проверяются `llama-server --version`
и `llama-server --help`. Без `--model-file` используется HF-кэш Qwen3.5-2B Q4_K_M;
при первом запуске модель может скачиваться. Для заранее скачанной модели передайте путь.

Ключ вводится без эха и не помещается в аргументы команды:

```bash
read -r -s TABLETOP_SERVICE_API_KEY
echo
export TABLETOP_SERVICE_API_KEY
.venv/bin/python tabletop-llm-service.py --model-file /path/to/Qwen3.5-2B-Q4_K_M.gguf
```

В zsh для скрытого ввода используйте `read -r -s '?Ключ сервиса: ' TABLETOP_SERVICE_API_KEY`.
Ключ должен быть непустым ASCII без пробелов. Можно создать его менеджером паролей.

По умолчанию шлюз слушает `127.0.0.1:8080`. Для второго устройства в домашней сети:

```bash
.venv/bin/python tabletop-llm-service.py --host <SERVER_LAN_IP> --model-file /path/to/model.gguf
```

Backend всегда слушает только `127.0.0.1:10099`. Порты можно менять через `--port` и
`--backend-port`, ожидание загрузки — `--start-timeout` (по умолчанию 120 секунд).
Если внутренний порт занят, чужой процесс не используется и не останавливается.
SIGINT/SIGTERM/SIGHUP завершают собственную модель сервиса. Убийство процесса через SIGKILL
не позволяет выполнить очистку; systemd дополнительно управляет всей группой службы.

Сетевой HTTP не шифрует данные. Используйте доверенную домашнюю сеть с разрешением порта
шлюза только нужным клиентам; для недоверенной сети нужен VPN или TLS перед шлюзом.

## HTTP API

| Запрос | Авторизация | Результат |
| --- | --- | --- |
| `GET /health` | Не нужна | Только готовность: 200 либо 503 |
| `GET /v1/models` | Bearer | Одна модель `tabletop-qwen-2b-q4-k-m-optimized` |
| `POST /v1/chat/completions` | Bearer | Непотоковый текстовый ответ `choices`, метрики `usage` |

Пример тела первого запроса:

```json
{
  "model": "tabletop-qwen-2b-q4-k-m-optimized",
  "messages": [{"role": "user", "content": "Сколько стоит дорога в CATAN?"}],
  "max_tokens": 1024,
  "temperature": 0.3
}
```

Второй запрос включает первый user, полученный assistant и новый user. Роли — только
`system`, `user`, `assistant`; контент — строка. Несколько system-блоков объединяются
в начале в исходном порядке. Допустимы также `seed`, `cache_prompt`, `stream=false`;
потоковый режим, инструменты и другая модель отклоняются.
Поле `reasoning_content`, возвращённое моделью у assistant, допускается при повторной
передаче ответа в истории и не включается в следующий prompt.

| Ограничение | Значение | Отказ |
| --- | --- | --- |
| Частота генерации | 10 запросов за скользящие 60 секунд на ключ | 429, `Retry-After` |
| Контекст | 8192 токена: шаблон чата + бюджет ответа + запас 2 токена | 400, `context_length_exceeded` |
| Ответ | 1–1024 токена, по умолчанию 1024 | 400 |
| Тело | До 128 КиБ | 413 |
| Исполнение | Один запрос выполняется, один ожидает | 503, `Retry-After` |
| HTTP-обработчики | Не больше 8 одновременно | 503 |
| Чтение запроса | Таймаут 10 секунд | 408 |
| Backend | Таймаут каждого HTTP-вызова 300 секунд | 504; недоступность/неверный ответ — 502 |

Корректно оформленные авторизованные запросы, отклонённые по контексту или очереди,
тоже входят в лимит частоты. `/health` и `/v1/models` его не расходуют. Проверка контекста
использует настоящий токенизатор и шаблон модели; история не обрезается. Модель работает
с отключённым context shift, одним слотом и thinking budget=256.

Журнал шлюза содержит идентификатор запроса, HTTP-статус и время, без содержимого чата,
заголовков и ключей. Вывод дочерней модели отключён. При ошибке запуска проверьте
наличие модели, версию llama.cpp и свободный внутренний порт.

## Подключение TUI

```bash
export TABLETOP_LLAMA_AUTOSTART=0
export TABLETOP_LOCAL_API_URL=http://<SERVER_LAN_IP>:8080/v1/chat/completions
read -r -s TABLETOP_LOCAL_API_KEY
echo
export TABLETOP_LOCAL_API_KEY
.venv/bin/python tabletop-ai-assistant.py
```

В zsh замените ввод на `read -r -s '?Ключ сервиса: ' TABLETOP_LOCAL_API_KEY`.
В `/models` выберите Qwen3.5-2B Q4_K_M, затем выполните `/local optimized` — её alias
совпадает с моделью сервиса, бюджет основного ответа равен 1024.

Для простого чата с этим сервисом отключите `/tool auto off` и RAG (`/rules mode off`),
используйте стратегию окна в `/settings`. Сервис предназначен для одной модели текстового
чата: embeddings и вспомогательные запросы с бюджетом больше 1024 он не обслуживает.
Для полного набора инструментов и RAG сохраняется прежний локальный router.

`TABLETOP_LOCAL_API_KEY` отправляется только локальным моделям. Облачный ключ
`OPENCODE_API_KEY` локальному сервису не передаётся. Без отдельного ключа прежний локальный
режим работает без Authorization. Для возврата к нему остановите сервис и удалите
`TABLETOP_LOCAL_API_URL`, `TABLETOP_LOCAL_API_KEY`, `TABLETOP_LLAMA_AUTOSTART` из окружения.

## Linux: systemd

Пример — `deploy/tabletop-llm.service`. Он предполагает пользователя `tabletop`, проект в
`/opt/tabletop-ai-assistant-tui`, GGUF в `/srv/tabletop/models/qwen-2b-q4-k-m.gguf` и
`llama-server` в `/usr/local/bin`. Исправьте пути под сервер. Пользователь службы должен
иметь право читать модель и запускать программу.

В `/etc/tabletop-llm.env` задайте `TABLETOP_SERVICE_API_KEY` и `TABLETOP_SERVICE_HOST`.
Создайте этот файл с правами 600 и владельцем root; значение ключа не выводите в терминал.
Адрес хоста — LAN-адрес Linux-сервера, не адрес SSH-клиента.

```bash
sudo install -m 644 deploy/tabletop-llm.service /etc/systemd/system/tabletop-llm.service
sudo systemctl daemon-reload
sudo systemctl enable --now tabletop-llm.service
sudo systemctl status tabletop-llm.service
```

Остановка: `sudo systemctl stop tabletop-llm.service`.

## Проверка дня 30

Автоматические тесты:

```bash
.venv/bin/python -m pytest tests/unit/test_private_llm_service.py tests/e2e/test_private_llm_service.py -q
```

Серия стабильности — ровно три последовательных вопроса настоящей модели: стоимость
дороги CATAN, подготовка CATAN, условие победы CATAN. Для каждого фиксируются HTTP 200,
непустой ответ и время. Отдельно проверяются два хода чата, 401 без ключа, переполнение
контекста, 429 и восстановление после окна частоты.

Сетевой доступ доказывается запросом с отдельной машины: SSH-сеанс этой машины открыт
в записываемом терминале, оттуда запрос идёт на LAN-адрес сервера. Реальные SSH-адреса
и материалы записи находятся только в исключённом из Git `videos/`; SSH-пароль не хранится
в скрипте и вводится скрыто. Loopback-запрос не является проверкой второго устройства.
