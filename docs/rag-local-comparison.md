# День 28: локальная LLM + RAG

Локальный RAG уже реализован в `c6dcb1e`: Qwen 3.5 отвечает через llama.cpp,
Qwen3-Embedding создаёт векторы, SQLite хранит фрагменты правил и векторы.
Облачный ключ не нужен и не передаётся в локальные запросы. При переключении
на облачную модель сохраняется локальный поиск по исходным хеш-векторам.

## Повторение проверки

Для сопоставимого прогона сначала подготовьте отдельную копию **готового**
индекса из корня проекта. Этот шаг сохраняет исходные тексты и идентификаторы;
основной индекс не меняется. Выполняйте один раз, затем используйте ту же копию.

```bash
.venv/bin/python - <<'PY'
import sqlite3
from pathlib import Path

root = Path.cwd()
folder = root / "videos/day28-corpus"
folder.mkdir(parents=True, exist_ok=True)
database = folder / "index.sqlite3"
if database.exists():
    raise SystemExit("Копия уже существует — используйте её")
with sqlite3.connect(f"file:{root / '.rules-index.sqlite3'}?mode=ro", uri=True) as source:
    with sqlite3.connect(database) as target:
        source.backup(target)
        target.execute("DELETE FROM chunks WHERE source NOT IN ('catan-rules.pdf', 'ticket-to-ride-rules.pdf')")
        if target.execute("SELECT 1 FROM sqlite_master WHERE name='model_embeddings'").fetchone():
            target.execute("DELETE FROM model_embeddings WHERE (strategy, chunk_id) NOT IN (SELECT strategy, chunk_id FROM chunks)")
        target.execute("UPDATE metadata SET value='2' WHERE key='files'")
        target.commit()
documents = folder / "documents"
documents.mkdir(exist_ok=True)
for name in ("catan-rules.pdf", "ticket-to-ride-rules.pdf"):
    (documents / name).symlink_to(root / "docs/rules" / name)
PY
TABLETOP_RULES_INDEX_FILE=videos/day28-corpus/index.sqlite3 \
TABLETOP_RULES_DOCUMENTS_DIR=videos/day28-corpus/documents \
TABLETOP_LLAMA_AUTOSTART=0 \
./tabletop-ai-assistant.py
```

Сервер основного измерения использует отдельную копию `llama_server/models.ini`.
Скопируйте её в `videos/day28-models.ini` и установите параметры:

| Секция | Параметры CPU-прогона |
| --- | --- |
| `[*]` | `b = 512`, `ub = 512`, `threads-batch = 6`; для демонстрации и повторения также `offline = true` |
| `unsloth/Qwen3.5-2B-GGUF:Q4_K_M` | `reasoning = off`, строка `reasoning-budget` удалена |
| `Qwen/Qwen3-Embedding-0.6B-GGUF:Q8_0` | `c = 2048` |

Запустите сервер в отдельном терминале **до приложения**:

```bash
llama-server --offline --host 127.0.0.1 --port 9999 --models-max 2 \
  --models-preset videos/day28-models.ini
```

Две модели остаются загруженными, чтобы повторный поиск не перезапускал
генератор. Рассуждение Qwen отключено только в экспериментальном профиле.
Настройки проекта не меняются. Эти результаты не измеряют профиль по умолчанию.
Флаг `offline` добавлен перед сухим прогоном и демонстрацией; во время основного
измерения блокировались внешние HTTP-запросы приложения, а веса уже были скачаны.

1. Скачайте модели из `llama_server/models.ini` и проверьте их командой
   `llama-server -cl`. Для локальной части удалите `OPENCODE_API_KEY` из окружения
   и `.env` либо используйте отдельный запуск с пустым ключом.
2. Запустите `./tabletop-ai-assistant.py`, выберите Qwen 3.5 2B в `/models`.
   `/rules` должен показывать готовый индекс CATAN и Ticket to Ride.
   Старый индекс недели 6 используется без повторного чтения PDF: первый поиск
   подготовит отсутствующие локальные векторы.
3. Выполните `/tool auto off`, `/rules mode on`, `/rules retrieval baseline`
   и `/rules tune before=5 after=3 threshold=0.6`. В `/settings` установите
   компактный формат, 80 слов и температуру 0.0. В `baseline` порог не применяется:
   используются первые три фрагмента локального векторного поиска.
4. Задайте все три вопроса из таблицы ниже. Перед каждым выполните `/clear`,
   после ответа — `/rules trace` и `/usage`. Повторите набор трижды.
5. Выберите `deepseek-v4.1-flash`, задайте те же вопросы с теми же настройками
   и повторениями. Для облачной части потребуется ключ.

| Вопрос | Независимый критерий качества |
| --- | --- |
| What resources are required to build one road in CATAN? | Один кирпич и одно дерево, всего две карты. Источник: `catan-rules.pdf`, `a) Road`, PDF-страница 4. |
| In Ticket to Ride, how many train car cards can I draw if I choose a face-up locomotive first? | Только одну карту; добор заканчивается. Ограничение не переносится на локомотив, вытянутый вслепую. Источник: `ticket-to-ride-rules.pdf`, `Train Car Cards`, PDF-страница 3. |
| How are points scored for placing a tile on the wall in Azul? | Правил Azul в корпусе нет. Успешный RAG не должен ссылаться на правила другой игры как на доказательство. Ожидается честное сообщение об отсутствии подтверждения. |

## Что измерять

- **Качество:** правильность фактов, релевантность переданного контекста,
  подтверждение ответа текстом фрагментов. В компактном формате автоматическая
  проверка дословных цитат не выполняется; источники показывает интерфейс.
  Наличие источника само по себе недостаточно.
- **Скорость:** полное время вопроса, включая локальный поиск,
  генерацию и повторные запросы проверок ответа. Строка ток/сек описывает отдельный запрос
  генерации, а не весь RAG. Подготовку векторов измерять отдельно.
- **Стабильность:** успешные и неудачные ответы, сбои поиска, ложные отказы,
  изменения фактов и источников между тремя повторениями. Это небольшой
  контрольный набор, а не оценка надёжности на всех вопросах.

Сравнение относится к двум системам целиком: локальная модель использует
Qwen3-Embedding, облачная — хеш-векторы. Режим сравнения — `baseline`;
вспомогательные запросы переписывания и реранжирования в нём не выполняются.
Разницу нельзя целиком приписывать генератору.
Для отдельной оценки генерации нужно передать обеим моделям одинаковые
фрагменты, что не является режимом этого прогона.

## Среда проверки

Проверка выполняется на CPU: установленный llama.cpp сообщает, что usable GPU
не найден. Полный исходный индекс содержит 1208 фрагментов фиксированного
разбиения и 1243 структурного, всего 2451. Для контрольного прогона по согласованию
с пользователем используется копия с CATAN и Ticket to Ride: 55 фиксированных
и 103 структурных фрагмента, всего 158. Тексты и идентификаторы взяты из готового
индекса недели 6; PDF повторно не читаются. D&D исключён только из этой копии.
Azul отсутствует и в исходном, и в контрольном корпусе.

Вопросы основного сравнения заданы на языке корпуса — английском. Предварительный
русский вопрос о стоимости дороги в `baseline` выбрал карту Road Building
и начальную расстановку вместо стоимости строительства; локальный ответ
отказался назвать цену. Этот результат показывает влияние языка и формулировки
на поиск; улучшение после перехода на английский нельзя считать общей гарантией
качества локальной модели.

История, память, профиль, задачи и планировщик контрольного прогона изолированы
в `videos/tmp/day28-benchmark-selected/`. Используется копия исходного SQLite-индекса.
Локальный этап блокирует HTTP-запросы приложения к внешним адресам; результаты
и журнал фактических запросов сохраняются рядом с индексом. Демонстрационный
сервер запускается с `--offline`, включая дочерние модельные процессы.

## Результаты: 2026-10-07

Основной набор: три вопроса, по три независимых повторения на каждой модели;
перед каждым вопросом очищена история. Корпус, вопросы, формат, объём и
температура совпадают. Порядок: весь набор, затем второй и третий круг.

| Метрика | Локальная Qwen 3.5 2B | Облачная deepseek-v4.1-flash |
| --- | ---: | ---: |
| Полное время вопроса, медиана | 117,68 с | 3,95 с |
| Диапазон времени | 57,39–228,14 с | 2,99–6,76 с |
| Запросы генерации | 9 | 9 |
| Входные / выходные токены | 20505 / 1097 | 24864 / 3611 |
| Стоимость по оценке приложения | $0 | $0,0117924 |
| Технически завершённый поиск | 9/9 | 9/9 |
| Непустой ответ | 9/9 | 8/9 |

Время измерено вокруг всего `agent.ask()`, включая локальный поиск и запросы
генерации. Токены и стоимость относятся к chat API; embedding-токены в журнале
использования приложения не учитываются. В локальной части зарегистрированы
18 HTTP-запросов приложения: 9 embedding и 9 chat, все на `127.0.0.1`.
Клиент локальной генерации создан с пустым облачным ключом. Первичная подготовка
векторов не входит в таблицу: завершающий проход по 158 фрагментам занял 82,0 с
с повторным использованием уже вычисленных векторов. Это не замер холодной
индексации полного корпуса.

### Качество и стабильность

| Проверка | Локальная модель | Облачная модель |
| --- | --- | --- |
| Цена дороги CATAN | Кирпич + дерево, 3/3 | Кирпич + дерево, 3/3 |
| Открытый локомотив Ticket to Ride | Ключевой лимит «одна карта», 3/3; в первом ответе выдуманное условие о пяти локомотивах | Правильный лимит в 2/3; один пустой ответ при `finish_reason=stop` |
| Azul отсутствует в корпусе | Ложный отказ «не по настольным играм» и выдуманный источник «Azul Rules (1jour-1jeu.com)», 3/3 | Признано отсутствие правил Azul, 3/3, но даны ответы из общих знаний без подтверждения корпусом |

Релевантные фрагменты стоимости дороги и открытого локомотива присутствуют
в локальном и облачном контексте во всех основных повторениях. Наборы выбранных
`chunk_id` внутри каждой системы для одного вопроса повторяются. Тексты ответов
меняются даже при температуре 0.0. Поэтому отдельно оценены стабильность поиска,
ключевые факты, дополнительные утверждения и наличие ответа.

Локальный путь действительно выполняет поиск и генерацию без облачной модели,
но малая Qwen 2B не гарантирует правильность всех дополнительных правил и
источников. Облачная система на этом наборе значительно быстрее и тоже имеет
сбои ответа. Успешный технический поиск не доказывает качество; одинаковые
плохие ответы не означают надёжность. На вопрос вне корпуса ни одна система
в режиме `baseline` + компактный формат не дала подтверждённый RAG-ответ.

Отдельный предварительный прогон `enhanced` на русском языке с тем же сокращённым
корпусом дал облачной модели три ответа с источниками для CATAN, три для Ticket
to Ride и три честных сообщения об отсутствии контекста для Azul. Это отдельный
режим, а не доказательство качества локального `enhanced`: его вспомогательные
запросы на CPU заметно увеличивают задержку.

Полный предварительный набор тестов существующей реализации: **1420 passed,
16 deselected**, 401,32 с; предупреждения Python о `forkpty`. Строгая проверка
OpenSpec: **23 passed, 0 failed**. В рамках дня 28 добавлен отчёт и уточнена
документация; реализация локальных embeddings уже заархивирована в изменении
`2026-10-06-use-local-rag-embeddings`.
