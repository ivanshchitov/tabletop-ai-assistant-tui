## ПРОМПТ ДЛЯ СОЗДАНИЯ TUI "TABLETOP AI ASSISTANT"

### НАЗВАНИЕ ПРОЕКТА
**Tabletop AI Assistant** — интеллектуальный TUI-ассистент по настольным играм на базе модели `deepseek-v4-flash`, доступной через OpenAI-совместимый эндпоинт OpenCode Zen.

---

### ОБЩАЯ ЗАДАЧА
Разработать консольное TUI-приложение **Tabletop AI Assistant**, которое:
- **Внутри себя содержит фиксированный системный промпт** (определяет роль ассистента) и **агентный промпт** (определяет логику работы, фильтрацию тем, формат ответов).
- Принимает от пользователя **только пользовательские промпты** (вопросы по настольным играм).
- **Строго фильтрует темы**: если вопрос не касается настольных игр — вежливо объясняет причину отказа и предлагает задать вопрос по теме.
- Имеет **единственную команду** — `/exit` для выхода из приложения, с **автодополнением по Tab**.
- Всё остальное взаимодействие — через ввод текста в TUI.
- Ответы ассистента отображаются как **отрендеренный Markdown** (заголовки, списки, выделение), а не как сырой текст.
- Вывод в терминал **только дописывается** — экран никогда не очищается, поэтому уже показанные вопросы, ответы и приглашения на ввод никогда не пропадают со временем.

---

### ВСТРОЕННЫЕ ПРОМПТЫ (HARDCODED)

#### 1. СИСТЕМНЫЙ ПРОМПТ (определяет роль)
```
Ты — эксперт по настольным играм (board games). Твоя специализация — правила, стратегии, разрешение спорных ситуаций, рекомендации и история настольных игр. Ты всегда отвечаешь вежливо, структурированно и по делу. Твоё имя — Tabletop AI Assistant.
```

#### 2. АГЕНТНЫЙ ПРОМПТ (определяет поведение и фильтрацию)
```
Твоя задача — обрабатывать только запросы, связанные с настольными играми.

Правила:
1. Если пользователь спрашивает о чём-либо, не относящемся к настольным играм (кино, еда, политика, технологии, личные вопросы и т.д.), ТЫ ОБЯЗАН ответить строго одной фразой:
   "Я не могу рассказать об этом, потому что я — Tabletop AI Assistant, и я работаю только с вопросами по настольным играм. Пожалуйста, задайте вопрос по теме."
   Никаких дополнительных пояснений, советов или переходов на другие темы.

2. Если вопрос касается настольных игр:
   - Отвечай структурированно: краткий ответ → детали → итог.
   - Форматируй ответ в Markdown: заголовки, **жирный текст**, маркированные и нумерованные списки.
   - Используй пункты, нумерацию, смайлики (🎲, 🏆, 🎯, 📖, ♟️) для ключевых моментов.
   - При разрешении спорных правил ссылайся на логику и официальные источники.
   - Для рекомендаций уточняй количество игроков, сложность, длительность, жанр.
   - Если игра неизвестна — предложи похожие игры или уточни описание.

3. Не задавай уточняющих вопросов, если тема не относится к играм — сразу выдавай отказ.
4. Если вопрос по играм, но слишком общий — дай развёрнутый ответ с примерами.
5. В начале каждого ответа представляйся: "Tabletop AI Assistant: [ответ]"
```

### ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

**Библиотеки:**
- `rich` — для построения TUI (Panel, Console, Live, Markdown, status-спиннер)
- `requests` — для HTTP-запросов к API
- `python-dotenv` — для загрузки API-ключа
- `readline` (стандартная библиотека, опционально) — для автодополнения команд по Tab; на платформах без него (Windows без `pyreadline3`) приложение просто работает без автодополнения

**API-взаимодействие:**
- Endpoint: `https://opencode.ai/zen/v1/chat/completions`
- Модель: `deepseek-v4-flash`
- Температура: `0.7`
- Максимальная длина ответа: `1000 токенов`
- Переменная окружения с ключом: `OPENCODE_API_KEY`

**Формат отправки запроса:**
```json
{
  "model": "deepseek-v4-flash",
  "messages": [
    {"role": "system", "content": "<СИСТЕМНЫЙ_ПРОМПТ>\n\n<АГЕНТНЫЙ_ПРОМПТ>"},
    {"role": "user", "content": "Вопрос пользователя: <текст>"}
  ],
  "temperature": 0.7,
  "max_tokens": 1000
}
```

### ИНТЕРФЕЙС TUI

Интерфейс реализован как **прокручиваемый (append-only) консольный лог** на базе `rich`, а не как полноэкранная панель с фиксированными зонами: заголовок и история не перерисовываются поверх друг друга, а последовательно дописываются в терминал, поэтому ничего из уже показанного (включая сами приглашения на ввод) никогда не стирается и не перекрывается заново.

**Пример вывода:**
```
╭──────────────────────────────────────────────────────────────╮
│ 🎲 TABLETOP AI ASSISTANT — эксперт по настольным играм       │
╰──────────────────────────────────────────────────────────────╯
🎲 Tabletop AI Assistant запущен. Задайте вопрос по настольным играм. /exit — выход.

> Введите вопрос (или /exit для выхода): Подскажи правила игры "Колонизаторы"
Вы: Подскажи правила игры "Колонизаторы"
Tabletop AI Assistant:
📖 Правила игры "Колонизаторы":
 1. Бросок кубиков...
 2. Торговля ресурсами...

Итог: ...
────────────────────────────────────────────────────────────────
Статус: Готов ✅  |  Команды: /exit — выход  |  Диалогов за сессию: 1
────────────────────────────────────────────────────────────────
> Введите вопрос (или /exit для выхода): Как приготовить пиццу?
Вы: Как приготовить пиццу?
Tabletop AI Assistant:
Я не могу рассказать об этом, потому что я — Tabletop AI Assistant, и я работаю
только с вопросами по настольным играм. Пожалуйста, задайте вопрос по теме.
────────────────────────────────────────────────────────────────
Статус: Готов ✅  |  Команды: /exit — выход  |  Диалогов за сессию: 2
────────────────────────────────────────────────────────────────
> Введите вопрос (или /exit для выхода):
```

**Элементы интерфейса:**
- **Заголовок** — печатается один раз при старте: панель с названием "Tabletop AI Assistant" и уточнением тематики.
- **Приветствие** — показывается один раз, только если сохранённая история пуста.
- **История диалога** — при старте, если `history.json` не пуст, весь сохранённый диалог один раз проигрывается в лог; далее каждый новый вопрос/ответ просто дописывается.
- **Ответ ассистента** — рендерится как Markdown (`rich.markdown.Markdown`): заголовки, списки, `**жирный текст**` отображаются форматированно, а не как обычный текст.
- **Разделитель** — горизонтальная линия после каждого блока "Вопрос-Ответ".
- **Приглашение на ввод** — обычный `input("> Введите вопрос (или /exit для выхода): ")` **без** ANSI/rich-разметки. Это принципиально: если передать в системный `input()` цветной текст через `rich`, `readline` неверно считает его видимую длину и при удалении введённых символов (backspace) портит/стирает само приглашение. Поэтому приглашение печатается как обычная строка — так `readline` точно знает его границы и никогда не затирает его.
- **Автодополнение по Tab** — список доступных команд (сейчас только `/exit`) зарегистрирован в `readline` как completer; при наборе `/e` + Tab строка дополняется до `/exit`. Реализация учитывает разницу между GNU readline (Linux) и libedit (macOS, "readline" на базе libedit) при биндинге клавиши Tab.
- **Статус-бар** — строка после каждого обмена репликами: индикатор готовности, список команд, счётчик диалогов за сессию. Во время ожидания ответа отдельно показывается пульсирующий спиннер "● Отправка...".

### ЛОГИКА РАБОТЫ

1. **Запуск приложения**:
   - Настраивается автодополнение команд по Tab (`readline`, если доступен).
   - Загружается API-ключ из `.env` (переменная `OPENCODE_API_KEY`); если ключа нет — выводится сообщение и предлагается ввести ключ вручную (цикл повторяется, пока ключ не будет введён). Ctrl+C на этом шаге (до того как приложение вообще начало работу) перехватывается отдельно: печатается прощальное сообщение *"До встречи! 🎲"* **без** упоминания сохранённой истории (диалогов ещё не было) и без вызова сохранения `history.json`, после чего приложение сразу завершается.
   - Загружается история диалога из `history.json` (если есть) и один раз проигрывается в лог.
   - Если истории нет — отображается приветствие: *"🎲 Tabletop AI Assistant запущен. Задайте вопрос по настольным играм. /exit — выход."*
   - Печатается строка статус-бара.

2. **Ввод пользователя**:
   - Если введено `/exit` → завершение работы с сохранением истории.
   - Если введён пустой текст → игнорируется, повторный запрос ввода.
   - Если введён текст → отправка запроса с **объединённым системным + агентным промптом**.
   - Если запрос длиннее 2000 символов → обрезается, выводится предупреждение.

3. **Обработка ответа**:
   - Во время ожидания ответа в статус-баре отображается спиннер "● Отправка...".
   - Полученный ответ дописывается в лог как Markdown с эффектом постепенного появления.
   - Если API вернул ошибку — сообщение об ошибке выводится и остаётся видимым в логе (не стирается), предлагается повторить запрос.
   - При успешном ответе — автоматическое сохранение диалога в `history.json`, обновление счётчика диалогов, печать новой строки статус-бара.

4. **Визуальные эффекты**:
   - Эффект "печати" ответа: текст постепенно наращивается небольшими фрагментами и на каждом шаге заново рендерится как Markdown через `rich.live.Live` (а не просто печатается слово за словом простым текстом).
   - Пульсирующий индикатор загрузки в статус-баре при отправке запроса.

### ОБРАБОТКА ОШИБОК

- **Отсутствие API-ключа** → вывод сообщения: *"API-ключ не найден. Добавьте OPENCODE_API_KEY в файл .env"* и предложение ввести ключ вручную.
- **Неверный API-ключ (HTTP 401)** → отдельное сообщение: *"Неверный API-ключ Deepseek."*
- **Таймаут API** → повторный запрос с экспоненциальной задержкой (макс. 3 попытки).
- **Ошибка соединения** → вывод сообщения: *"Ошибка соединения с Deepseek API. Проверьте интернет-соединение."* (без повторных попыток — это сетевая, а не временная проблема).
- **Прочие ошибки HTTP / некорректный ответ API** → отдельные понятные сообщения об ошибке.
- **Пустой ввод** → игнорируется (не отправляется).
- **Слишком длинный запрос** (>2000 символов) → предупреждение и обрезка до 2000 символов.
- **Ctrl+C** → перехватывается на всех этапах, где возможен ввод или ожидание, и никогда не приводит к необработанному traceback:
  - во время ручного ввода API-ключа (до старта основного цикла) — приложение выводит *"До встречи! 🎲"* (без упоминания истории, так как сохранять ещё нечего) и завершается;
  - во время ввода вопроса, ожидания ответа API или анимации печати ответа — приложение выводит `GOODBYE_MESSAGE` *"До встречи! История диалога сохранена. 🎲"*, сохраняет `history.json` и завершается.
- Сообщения об ошибках не исчезают при следующем действии — они остаются в логе, так как экран никогда не очищается.

### КОДОВАЯ СТРУКТУРА

Исходный код лежит плоско в корне репозитория (без отдельного пакета) — модулей немного, и вложенный пакет для них избыточен:

```
tabletop-ai-assistant-tui/
├── tabletop-ai-assistant.py   # Точка входа, запуск TUI (было main.py)
├── tui_app.py                 # Основной класс TabletopAITUI (rich + readline-автодополнение)
├── api_client.py               # Класс DeepseekAPIClient (retry с backoff, обработка ошибок)
├── history_manager.py          # Сохранение/загрузка истории
├── config.py                   # Загрузка переменных окружения, URL/модель API
├── prompts.py                  # Системный и агентный промпты
├── history.json                # Сохранённая история (в .gitignore, создаётся при первом ответе)
├── .env                         # OPENCODE_API_KEY=sk-... (в .gitignore)
├── .env.example                 # Шаблон .env
├── requirements.txt             # rich, requests, python-dotenv
├── create-tui-prompt.md         # Эта спецификация
├── README.md
└── LICENSE
```

Точка входа named `tabletop-ai-assistant.py` (с дефисом) — она не импортируется другими модулями (дефис делает имя невалидным как идентификатор Python), а только запускается напрямую: `python tabletop-ai-assistant.py`. Остальные модули (`tui_app.py`, `api_client.py` и т.д.) используют обычные плоские импорты (`import config`, `from tui_app import TabletopAITUI`), которые работают, пока все файлы лежат в одной директории.

### ТРЕБОВАНИЯ К ВИЗУАЛИЗАЦИИ

- **Цветовая схема**:
  - Вопросы пользователя — **синий** (`bold blue`), префикс "Вы:"
  - Имя ассистента-подписи перед ответом — **фиолетовый** (`bold magenta`), "Tabletop AI Assistant:"
  - Сам ответ ассистента — рендерится как **Markdown** (собственная типографика `rich.markdown.Markdown`: жирный, заголовки, списки), без принудительной сплошной заливки одним цветом
  - Системные сообщения (приветствие, предупреждения) — **жёлтый** (`bold yellow`)
  - Сообщения об ошибках — **красный** (`bold red`)
  - Заголовок приложения — **голубой** (`bold cyan`)
  - Строка статус-бара — приглушённый стиль (`dim`)

- **Разделители**:
  - Горизонтальная линия после каждого блока "Вопрос-Ответ" и после сообщения об ошибке.

- **Анимации**:
  - Пульсирующий спиннер при отправке запроса (`rich.console.status`, spinner "dots").
  - Постепенное появление ответа с перерисовкой как Markdown (`rich.live.Live`), а не посимвольная/пословная печать простого текста.

- **Никакой очистки экрана**: приложение ни разу не вызывает очистку терминала — весь вывод, включая приглашения на ввод, остаётся в скроллбэке до конца сессии.

---

### ДОПОЛНИТЕЛЬНЫЕ ОСОБЕННОСТИ

1. **Автосохранение** — история сохраняется в `history.json` после каждого успешного ответа.
2. **Ограничение истории** — хранится последние 50 диалогов.
3. **Автодополнение команд по Tab** — через `readline`, список команд централизован (`COMMANDS`), легко расширяем.
4. **Устойчивое к backspace приглашение ввода** — приглашение печатается как обычная строка через встроенный `input()`, без встраивания rich/ANSI-разметки в сам текст, который видит `readline`; это исключает визуальную порчу приглашения при удалении введённого текста.
5. **Статистика** — отображение количества диалогов за сессию в статус-баре.
6. **Кроссплатформенность** — корректная работа на Windows/Linux/macOS; на платформах без модуля `readline` автодополнение молча отключается, остальной функционал не страдает.
