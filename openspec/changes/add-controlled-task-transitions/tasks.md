## 1. Таблица переходов и шлюз

- [x] 1.1 Тест: `TRANSITIONS` содержит ровно четыре этапа, разрешает `Planning→Execution`,
      `Execution→{Validation, Planning}`, `Validation→{Done, Execution}` и не даёт переходов из `Done`;
      переход этапа в себя запрещён (`tests/unit/test_task_state.py`).
- [x] 1.2 Тест: `transition()` принимает разрешённый переход, отклоняет недопустимый с причиной и не меняет
      состояние при отказе.
- [x] 1.3 Реализация: `TRANSITIONS`, `Transition`, `TransitionResult`, `TransitionError`, `transition()` и
      `allowed_transitions()` в `core/task_state.py`.

## 2. Предусловия этапов

- [x] 2.1 Тест: переход в `Execution` отклоняется, когда плана нет, когда ожидается ответ о правках и когда
      запрошено перестроение плана; принимается после принятия плана.
- [x] 2.2 Тест: переход в `Done` отклоняется из `Planning` и из `Execution`, принимается из `Validation`.
- [x] 2.3 Реализация: предусловия внутри шлюза; все смены этапа в `core/task_state.py` идут через шлюз,
      прямых правок `stage` не остаётся.

## 3. Журнал переходов

- [x] 3.1 Тест: принятый и отклонённый переходы записываются в журнал задачи с этапами, признаком и причиной.
- [x] 3.2 Тест: журнал ограничен пределом записей, старые вытесняются; журнал сериализуется в `task.json` и
      читается обратно, файл прежней формы даёт пустой журнал.
- [x] 3.3 Реализация: `TaskItem.transitions`, `config.MAX_TRANSITION_LOG`, запись в шлюзе, сериализация в
      `TaskStore`.

- [x] 4.2 Тест: возврат проверки в `Execution` и перестроение плана по правкам тоже проходят через шлюз и
