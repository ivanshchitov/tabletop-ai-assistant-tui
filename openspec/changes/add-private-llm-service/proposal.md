## Why

Локальная модель сейчас обслуживает один терминальный сеанс. Для дня 30 нужен приватный AI-сервис на домашнем сервере: отдельный процесс, сетевой HTTP API, чат и проверяемые ограничения.

## What Changes

- Отдельный запуск Qwen3.5-2B Q4_K_M через llama.cpp и HTTP-шлюз на домашнем сервере; сервис переживает закрытие TUI.
- Доступ по отдельному ключу, ограничение частоты запросов, размера тела, контекста и длины ответа, ограниченная очередь исполнения.
- Подключение существующего TUI по сетевому адресу с отдельным ключом локального сервиса.
- Инструкция запуска на macOS и пример systemd-службы для домашнего Linux-сервера.
- Проверка реальной модели: три последовательных вопроса, чат из двух ходов, отказы при нарушении ограничений и запрос с другого устройства.

## Capabilities

### New Capabilities

- `private-llm-service`: самостоятельный приватный сервис, HTTP-контракт, ограничения и подключение клиента.

### Modified Capabilities

Нет. Существующий режим автозапуска локального сервера и отсутствие облачного ключа в локальных запросах сохраняются. Сервисный режим включается явно.

## Impact

- Новые `llm_service/` и `tabletop-llm-service.py`: запуск, HTTP-шлюз и политика ограничений.
- `core/config.py`, `core/api_client.py`: отдельный ключ сервиса; существующий `TABLETOP_LOCAL_API_URL` задаёт адрес.
- Параметры отдельного серверного процесса задают фиксированный профиль сервисной модели; действующий `llama_server/models.ini` сохраняется.
- `docs/private-llm-service.md`, `deploy/tabletop-llm.service`, `README.md`, `CLAUDE.md`: установка, переменные и эксплуатация.
- `tests/unit/test_private_llm_service.py`, `tests/unit/test_api_client.py`, `tests/unit/test_config.py`, `tests/e2e/test_private_llm_service.py`: ограничения, контракт клиента и HTTP-сценарии.
- Новые постоянные файлы пользовательского состояния не нужны. История остаётся у клиента; сервер не сохраняет тексты запросов и ключи.
- Сетевые адреса, SSH-логин и пароль демо не включаются в отслеживаемые файлы; материалы демо хранятся только в исключённом из Git `videos/`.

## Acceptance Criteria

Дословные пункты задания дня 30:

Разверните локальную LLM как сервис:

- на VPS или домашнем сервере
- с HTTP API
- с возможностью чата

Проверьте:

- доступ к модели по сети
- стабильность при нескольких запросах
- базовые ограничения (rate limit / max context)

Результат: Приватный AI-сервис на базе локальной LLM.
Формат: Видео + Код.

Уточнения пользователя: серия стабильности содержит ровно три вопроса; второй клиент — ALT Linux, подключение по SSH видно в терминале Mac; адрес используется только в демо; пароль вводится скрыто, не сохраняется в репозитории и не выводится на экран.

Сценарий демо (2–4 минуты, уточнить длительность сухим прогоном):

1. Показать отдельный запущенный сервис и его готовность.
2. Открыть с Mac SSH-сеанс второго устройства; выполнить сетевой HTTP-запрос к сервису.
3. Показать три последовательных ответа на короткие вопросы о настольных играх и результат проверки HTTP-статусов/времени.
4. В TUI показать два хода чата с продолжением контекста и закрыть клиент; сервис остаётся доступным.
5. Показать отказ без ключа, отказ при превышении частоты и переполнении контекста; после ограничений обычный запрос проходит.

Коммиты: предложить логически связанные группы «сервис», «подключение клиента», «документация и архив»; каждый коммит только после показа diff и подтверждения пользователя.
