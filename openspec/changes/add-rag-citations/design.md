## Context

См. `proposal.md` — Why. День 23 даёт готовый конвейер RAG: `rules_index.search` возвращает `SearchResult(source, title, section, chunk_id, text, score, strategy)`, `rules_retrieval` переписывает запрос и отбирает кандидатов по порогу, агент кладёт отобранные фрагменты в одно system-сообщение (`rules_index.context_message`) и печатает источники строкой (`ui/tui_app._print_rules_sources`). Статус поиска уже различает `ok`, `no_matches`, `no_candidates`, `no_index`, `rewrite_failed`, `rerank_failed`.

Инварианты (день 14) задают образец обязательной проверки ответа кодом: инструкция в system-сообщении, детерминированная проверка, один повтор с перечнем нарушений, затем замена ответа приложения — в диалог и историю идёт только показанный текст.

## Goals / Non-Goals

**Goals:**

- Ответ RAG подтверждается кодом: источники и цитаты, буквально взятые из переданных чанков.
- Слабый контекст (`no_matches` в `enhanced`) честно превращается в «не знаю» с уточнением — без запроса к модели.
- Механизм тестируется без терминала и без сети; терминальный слой рендерит снимок.

**Non-Goals:**

- Не менять контракты форматов JSON и compact и не добавлять новых команд.
- Не оценивать автоматически смысловое соответствие ответа цитатам — это делает контрольный прогон.
- Не трогать алгоритм поиска, порог, top-K и реранкер дня 23.

## Decisions

**Проверка цитат живёт в отдельном модуле `core/rules_citations.py`.** По образцу `invariants.py` и `mcp_tools.py`: чистые функции над текстом ответа и переданными чанками, без `rich` и HTTP. Так проверку можно покрыть unit-тестами, а агент только вызывает её. Альтернатива — держать проверку в агенте: хуже тестируется и смешивает сборку запроса с валидацией.

**Инструкция цитат — отдельный asset и system-сообщение, только при непустых источниках и свободном формате.** JSON сохраняет машиночитаемый контракт (`{"error": ...}` для не-карточных вопросов), compact-карточка — свой STRICT «ничего лишнего»; оба — задокументированные решения прошлых дней, ломать их ради цитат нельзя. Свободный формат — основной путь ответа по правилам. Приложение всё равно печатает источники RAG отдельной строкой, поэтому provenance виден при любом формате.

**Проверка: `chunk_id`/файл в тексте + дословная цитата.** Цитата считается подтверждённой, если после нормализации (нижний регистр, схлопывание пробелов) она длиной ≥ `config.CITATION_MIN_CHARS` (20) является подстрокой текста хотя бы одного переданного чанка. Названным источником считается встреча `chunk_id` или файла любого переданного фрагмента. Это намеренно буквальная проверка, а не семантическая: она гарантирует анти-галлюцинацию (цитата не выдумана) и остаётся детерминированной. Семантику сверяет контрольный прогон.

**Нарушение → один повтор → замена, как у инвариантов.** Повтор — продолжение того же диалога (ответ модели ходом `assistant`, перечень нарушений ходом `user`). При исчерпании повтора ответ заменяется фиксированным текстом о незнании с просьбой уточнить; в лог и историю идёт только он. `last_citations` — снимок (`violations`, `retried`, `replaced`) для журнальных строк TUI, по образцу `InvariantsCheck`.

**`no_matches` — единственный триггер «не знаю».** Только `enhanced` оценивает релевантность порогом; `baseline` порога не имеет, `no_candidates` (пустой индекс) не даёт оценок вообще, `no_index`/выключенный RAG — прежнее поведение. Гейт не вызывает модель и не пишет в ledger. Текст-незнание задаётся константой в `rules_citations`; агент возвращает его как ответ, TUI печатает и не печатает строку `⏱` (гейт различается по снимку `last_citations`, а не по нулевым токенам).

**`source` в заголовке фрагмента.** `context_message` и `SearchResult` уже несут `source`; заголовок расширяется до `[source | title; section; chunk_id]`, а TUI печатает `title — section (chunk_id) — source`. Это данные индекса, они не переписываются — как и требует день 23.

## Risks / Trade-offs

- [Ложный отказ: модель забыла формат блока → ответ заменён] → снижается явной инструкцией в asset и одним повтором с перечнем нарушений; повтор дешёв, а замена честнее выдуманной цитаты.
- [Ретрай добавляет запрос к каждому RAG-ответу при нарушении] → только при нарушении; корректный ответ стоит один запрос, как раньше.
- [Буквальная проверка цитат отвергает перефразированную цитату] → намеренно: перефраз — уже не цитата; инструкция требует дословности.
- [`no_matches` теперь перехватывает и посторонние вопросы при включённом RAG с индексом] → сознательно: «не знаю» честнее ответа без контекста; вне RAG/индекса поведение прежнее.
- [Расширение заголовка фрагмента меняет текст system-сообщения RAG] → снапшоты e2e, зависящие от него, обновляются осознанно после проверки; тесты агента фильтруют RAG-сообщение.

## Migration Plan

Обратной миграции не требуется: поведение включается только при готовом индексе и непустых источниках, состояние на диске не меняется, новые файлы состояния не появляются.
