## ADDED Requirements

### Requirement: Панель команд /commands
Команда `/commands` SHALL открывать интерактивную панель со списком всех поддерживаемых команд, каждая — с кратким описанием. Панель работает по той же схеме, что экраны `/settings` и `/logictask`: логика клавиш — в чистом редьюсере, тестируемом без терминала. Клавиши: ↑/↓ — перемещение выбора, Enter — выполнение выбранной команды, Esc — отмена. До подтверждения панель не делает вызовов модели и не меняет состояние приложения. Выбранная команда SHALL выполняться так же, как если бы пользователь набрал её в приглашении: `/settings` открывает экран настроек, `/clear` очищает историю, `/logictask` открывает панель стратегий, повторный выбор `/commands` заново открывает панель, `/exit` завершает приложение с сохранением истории. Выполнение MUST NOT зависеть от возможностей построчного редактирования терминала (readline/libedit). После закрытия панели (выполнением или отменой) SHALL печататься статус-бар.

#### Scenario: Список с описаниями
- **WHEN** пользователь вводит `/commands`
- **THEN** открывается панель, где видны все команды (включая `/commands` и `/exit`) и краткое описание каждой

#### Scenario: Выбор выполняет команду
- **WHEN** пользователь выбирает `/clear` и нажимает Enter
- **THEN** панель закрывается, история очищается, печатается сообщение об очистке и статус-бар

#### Scenario: Выбор экрана настроек
- **WHEN** пользователь выбирает `/settings` и нажимает Enter
- **THEN** открывается экран настроек, как при наборе команды вручную

#### Scenario: Выход из панели
- **WHEN** пользователь выбирает `/exit` и нажимает Enter
- **THEN** приложение завершается с сообщением о сохранённой истории

#### Scenario: Повторный выбор /commands
- **WHEN** пользователь на панели выбирает `/commands` и нажимает Enter
- **THEN** панель открывается заново

#### Scenario: Отмена по Esc
- **WHEN** пользователь открыл `/commands` и нажал Esc
- **THEN** панель закрывается, ничего не выполнено, печатается статус-бар

#### Scenario: /commands без аргументов-эффектов
- **WHEN** пользователь вводит `/commands ещё-что-то`
- **THEN** аргумент игнорируется, панель открывается как обычно

## MODIFIED Requirements

### Requirement: Команды и их распознавание
Приложение SHALL поддерживать команды: `/exit` (выход с сохранением истории), `/commands` (интерактивная панель всех команд с описаниями), `/settings` (экран настроек), `/clear` (очистка истории) и `/logictask` (интерактивная панель выбора одной стратегии решения фиксированной задачи; ↑/↓ — выбор, Enter — запуск, Esc — отмена). Распознавание команды — по первому слову ввода; аргументы после команды игнорируются. `/exit` MUST распознаваться только при точном совпадении всего ввода. Ввод, начинающийся с `/`, но не являющийся известной командой, SHALL отправляться модели как обычный вопрос. Список команд SHALL подсказываться автодополнением по Tab и SHALL выводиться из того же источника, что и панель `/commands`.

#### Scenario: Выход
- **WHEN** пользователь вводит `/exit`
- **THEN** приложение завершается с сообщением о сохранённой истории

#### Scenario: /exit с хвостом — это вопрос
- **WHEN** пользователь вводит `/exit, пожалуйста`
- **THEN** ввод не завершает приложение, а уходит модели как вопрос

#### Scenario: Неизвестная команда
- **WHEN** пользователь вводит `/foo`
- **THEN** ввод отправляется модели как обычный вопрос

#### Scenario: Аргументы игнорируются
- **WHEN** пользователь вводит `/settings что-то`
- **THEN** открывается экран настроек

#### Scenario: Автодополнение по Tab
- **WHEN** пользователь набирает `/se` и нажимает Tab
- **THEN** ввод дополняется до известной команды

#### Scenario: Автодополнение /commands
- **WHEN** пользователь набирает `/co` и нажимает Tab
- **THEN** ввод дополняется до `/commands`

#### Scenario: Запуск прогонов
- **WHEN** пользователь вводит `/logictask`
- **THEN** открывается панель выбора стратегии, и до подтверждения выбора запросов к модели нет

#### Scenario: /logictask с хвостом
- **WHEN** пользователь вводит `/logictask ещё`
- **THEN** аргумент игнорируется и прогон запускается

#### Scenario: Панель команд
- **WHEN** пользователь вводит `/commands`
- **THEN** открывается панель всех команд с описаниями, без запросов к модели

### Requirement: Статус-бар после каждого шага
После каждой команды и каждого обмена SHALL печататься статус-бар с текущим форматом, объёмом, лимитом списка, температурой, подсказкой команд и счётчиком диалогов за сессию, после чего — разделительная линия. В подсказке команд SHALL оставаться только `/exit` и `/commands`; полный список с описаниями доступен на панели `/commands`. Счётчик диалогов SHALL учитывать только обмены текущей сессии, а не восстановленную историю.

#### Scenario: Статус-бар после ответа
- **WHEN** модель ответила на вопрос
- **THEN** статус-бар показывает активные настройки (включая температуру), подсказку «Команды: /exit, /commands» и увеличившийся счётчик сессии

#### Scenario: Статус-бар после смены настроек
- **WHEN** пользователь изменил настройки и закрыл экран настроек
- **THEN** статус-бар отражает новый формат и новую температуру

#### Scenario: В статус-баре не перечислен полный список
- **WHEN** печатается любой статус-бар
- **THEN** в подсказке команд нет `/settings`, `/clear` и `/logictask`
