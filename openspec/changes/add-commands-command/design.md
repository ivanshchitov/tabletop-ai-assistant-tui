## Context

Главный цикл (`ui/tui_app.py`) — append-only журнал + `input()` с readline-автодополнением из плоского `COMMANDS`. Статус-бар печатает весь `COMMANDS` как подсказку. Интерактивные панели (`/settings`, `/logictask`) уже следуют схеме: чистый редьюсер в отдельном модуле `ui/*_screen.py`, в `tui_app` — только `keyboard.raw_mode()` + transient `Live` + цикл «read-key → redraw». Панели закрываются Enter/Esc; после команды печатается статус-бар.

См. proposal.md (Why) и specs/terminal-ui/spec.md (что должно работать).

## Goals / Non-Goals

**Goals**
- Панель `/commands` в стиле существующих панелей, тестируемая как редьюсер без терминала.
- Вставка выбранной команды в поле ввода; запуск — только Enter пользователя.
- Подсказка команд в статус-баре — только `/exit` и `/commands`.

**Non-Goals**
- Запуск команды прямо из панели (Enter в панели = подтверждение выбора, не запуск).
- Новые команды, фильтр/поиск по панели, пагинация.
- Убирать полный список из автодополнения.

## Decisions

**1. Редьюсер `ui/commands_screen.py` (не логика в tui_app).**
Аналог `settings_screen`/`logictask_screen`: `COMMAND_OPTIONS: List[Tuple[str, str]]` (команда, описание), `initial_state() -> CommandsScreenState(selected_index=0)`, `apply_key(state, key) -> state` (UP/DOWN с зацикливанием, ENTER/ESC — стоп-состояния, остальные клавиши игнорируются). Причина: единообразие с существующими панелями и юнит-тестируемость без pty. Альтернатива — обработка клавиш прямо в цикле tui_app — отвергнута: там уже два таких цикла, третий без редьюсера размножает непротестируемую логику.

**2. Источник списка команд — `ui/commands_screen.COMMAND_OPTIONS`; `COMMANDS` в tui_app выводится из него.**
Один источник правды для панели и автодополнения: `COMMANDS = [cmd for cmd, _ in COMMAND_OPTIONS]`. Порядок: `/exit`, `/commands`, `/settings`, `/clear`, `/logictask`. Альтернатива — два независимых списка — отвергнута: рассинхрон при добавлении команды.

**3. Подсказка статус-бара — отдельная константа `STATUS_COMMANDS = ["/exit", "/commands"]`.**
`COMMANDS` продолжает обслуживать автодополнение (полный список), статус-бар печатает только `STATUS_COMMANDS`. Альтернатива — печатать весь список маленьким шрифтом — отвергнута требованием спеки.

**4. Прямое выполнение выбранной команды (без зависимости от readline).**
Ревизия в ходе реализации: исходный план «вставить команду в буфер readline через startup-хук, подтверждает пользователь» не работает на libedit — readline в macOS-питоне (`/usr/bin/python3`) молча игнорирует и `rl_startup_hook`, и `insert_text` (проверено против живого pty). Поэтому Enter в панели теперь выполняет выбранную команду напрямую — по схеме `/logictask`, где Enter тоже запускает выбранное. Панель возвращает выбранную команду; диспетчер `_handle_command` исполняет её тем же кодом, что и ручной набор: `/settings` → `_open_settings_screen`, `/clear` → очистка, `/logictask` → `_run_logictask`, `/commands` → панель открывается заново (цикл внутри обработчика), `/exit` → `self._exit()` и сигнал остановки главного цикла (`self._exit_requested`). Отказ от вставки убирает ветвление по `readline.__doc__`, one-shot-хук и `_pending_input` — поведение идентично на GNU readline, libedit и без readline вовсе. Альтернатива — оставлять вставку только для GNU — отвергнута: поведение зависит от сборки питона, что и породило баг-репорт.

**5. Рендер панели — transient `Live`, как у `/logictask`.**
Стрелка `➤` + `[reverse bold]` на выбранной строке, футер `↑/↓ — выбор, Enter — вставить, Esc — отмена`. Постоянный лог панели не печатает: содержимое панели не нужно в скроллбеке, а результат (вставленная команда) виден в приглашении. Рендер — метод `_render_commands_panel` в tui_app рядом с `_render_logictask_panel`.

**6. Диспетчер: `if command == "/commands": self._open_commands_screen(); return True`** в `_handle_command`. Аргументы после `/commands` игнорируются — общее правило распознавания.

## Risks / Trade-offs

- [readline-хук не сработает, если пользователь прервёт input() не через Enter] → хук one-shot, снимается в finally после чтения строки; EOF/Ctrl+C идут по существующим веткам выхода.
- [Вставленный текст путают с автодополнением] → подсказка панели явно говорит «Enter — вставить»; вставленная команда видна в поле ввода и стирается Backspace.
- [e2e: байт, отправленный сразу после закрытия raw-mode-экрана, может пропасть при возврате в канонический режим (PENDIN-глитч)] → тест выполнения выбора для выхода из панели использует `/clear`, а не экран настроек: подтверждение не требует raw-mode-переключателя; переключение режимов экраном настроек проверено существующими тестами `/settings`.
- [e2e: flaky из-за Live-перерисовок] → как в test_strategies.py: ждать появления хинта панели перед отправкой стрелок и `wait_until_gone` после закрытия; проверки выполнения — по видимому эффекту команды (сообщение «История диалога очищена.», экран «Настройки»).
- [Снапшоты статус-бара разъедутся] → после правки статус-бара перегнать `pytest --snapshot-update` (осознанное изменение вёрстки).
