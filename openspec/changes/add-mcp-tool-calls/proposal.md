## Why

Сейчас приложение умеет только подключиться к чужим MCP-серверам и показать список их инструментов: ни один инструмент ни разу не вызывается, и результат работы сервера до ответа модели не доходит. Задача дня 17 требует собственный MCP-сервер вокруг реального API с регистрацией инструмента, описанием входных параметров и возвратом результата, а со стороны приложения — вызов этого инструмента и использование полученного результата в ответе.

## What Changes

- Проект получает **собственный MCP-сервер** над публичным API правил D&D 5e (`dnd5eapi.co`): серверный скрипт лежит вне пакетов `core/` и `ui/`, говорит по транспорту stdio и объявляет три обобщённых инструмента, покрывающих все разделы API — список доступных разделов, поиск по разделу и запись раздела по идентификатору. У поиска и записи есть необязательный параметр ветки правил со значениями `2014` и `2024`; по умолчанию используется `2014`.
- Каждый инструмент объявляет **схему входных параметров**: обязательные и необязательные поля, их типы, допустимые значения и значения по умолчанию. Неизвестный раздел, пустое имя и неверная ветка правил отклоняются понятным текстом, а не падением сервера.
- Свой сервер добавляется **записью в реестре описаний** рядом с уже подключёнными: имена инструментов и адрес источника данных по-прежнему не встречаются в коде приложения.
- Клиент MCP получает **вызов инструмента**: соединение поднимается на один вызов и закрывается, результат возвращается текстом, а любой сбой — данными снимка, а не исключением наружу.
- Появляется команда `/tool` со значащими аргументами: `list` — инструменты реестра вместе с их входными параметрами и без единого запроса к модели, `call <сервер>.<инструмент> ключ=значение` — ручной вызов с печатью результата, `auto on|off` — переключатель автоматического вызова.
- Появляется **автоматический вызов**: перед обычным вопросом отдельный запрос к модели выбирает инструмент и аргументы, приложение разбирает ответ само, вызывает инструмент и подмешивает результат в запрос отдельным системным сообщением выше диалога. Сбой выбора, отказ сервера или отсутствие подходящего инструмента не блокируют ответ: вопрос уходит как прежде, а в журнале появляется строка о том, что инструмент не вызван.
- Адрес внешнего API задаётся переменной окружения, поэтому автоматический прогон ходит в локальную заглушку и никогда — в сеть.

## Capabilities

### New Capabilities

Новых способностей нет: работа расширяет существующую интеграцию MCP.

### Modified Capabilities

- `mcp-integration`: добавляются требования к собственному серверу проекта над внешним API, к вызову инструмента и снимку его результата, к автоматическому выбору инструмента перед вопросом и к месту результата в запросе к модели.
- `terminal-ui`: в перечень команд добавляется `/tool` со значащими аргументами, добавляются требования к подкомандам `list`/`call`/`auto` и к строкам журнала о вызове инструмента.
- `configuration`: в перечень переменных переопределения добавляется адрес внешнего API собственного сервера.
- `test-infrastructure`: фейковый MCP-сервер обязан отвечать на вызовы инструментов, чтобы проверки вызова не поднимали настоящий сервер и не ходили в сеть.

## Impact

- Новый каталог `mcp_server/` со скриптом сервера и его модулями — вне `core/` и `ui/`, как самостоятельный процесс.
- `core/config.py`: запись реестра для своего сервера, адрес внешнего API и его переменная окружения.
- `core/mcp_client.py`: вызов инструмента и схемы входных параметров в снимке инструмента.
- `core/tabletop_agent.py`: снимок результата вызова, автоматический выбор инструмента, системное сообщение с результатом, новая фаза индикации.
- `ui/tui_app.py` и перечень команд: команда `/tool`, её подкоманды и строки журнала.
- `assets/`: инструкция выбора инструмента для модели.
- Тесты: юниты на сервер против локальной HTTP-заглушки, юниты на вызов инструмента против `tests/fake_mcp_server.py`, юниты на разбор выбора, e2e-проверки `/tool` и автоматического вызова, контрактная проверка живого API под маркером `network`.
- Документация: `CLAUDE.md` и `README.md` — новая команда, новая переменная окружения, новый каталог, новые тестовые файлы.
