## ADDED Requirements

### Requirement: Собственный MCP-сервер проекта над внешним API
Проект SHALL включать собственный MCP-сервер, работающий по транспорту stdio и получающий данные из внешнего публичного API правил настольной ролевой игры. Сервер SHALL объявлять три обобщённых инструмента, покрывающих все разделы этого API: перечень доступных разделов, поиск записей внутри раздела и получение полной записи раздела по её идентификатору. Перечень разделов SHALL браться у самого API, а не задаваться списком в коде сервера. Адрес внешнего API SHALL переопределяться переменной окружения, чтобы автоматический прогон обращался к локальной заглушке и не выходил в сеть. Отказ внешнего API (недоступность, таймаут, неизвестная запись) SHALL возвращаться вызывающей стороне текстом результата с описанием причины и SHALL NOT завершать серверный процесс.

#### Scenario: Сервер объявляет свои инструменты
- **WHEN** клиент подключается к собственному серверу проекта и запрашивает список инструментов
- **THEN** сервер отдаёт три инструмента с именами и описаниями: перечень разделов, поиск по разделу и запись по идентификатору

#### Scenario: Разделы приходят от внешнего API
- **WHEN** вызван инструмент перечня разделов
- **THEN** ответ содержит разделы, перечисленные самим внешним API

#### Scenario: Запись раздела возвращается по идентификатору
- **WHEN** вызван инструмент записи с известным разделом и известным идентификатором
- **THEN** ответ содержит поля записи, как их отдал внешний API

#### Scenario: Поиск по разделу ограничен лимитом
- **WHEN** вызван инструмент поиска с запросом и лимитом записей
- **THEN** ответ содержит не больше указанного числа найденных записей

#### Scenario: Внешний API недоступен
- **WHEN** внешний API не отвечает или возвращает ошибку
- **THEN** результат вызова несёт текст о причине сбоя, а серверный процесс продолжает работать

#### Scenario: Адрес внешнего API переопределён
- **WHEN** задана переменная окружения с адресом внешнего API
- **THEN** сервер обращается по указанному адресу, а адрес по умолчанию не используется

### Requirement: Описание входных параметров инструмента
Каждый инструмент собственного сервера SHALL объявлять схему входных параметров: имя каждого параметра, его тип, назначение, обязательность и — там, где набор значений ограничен, — допустимые значения со значением по умолчанию. Инструменты поиска и записи SHALL принимать необязательный параметр ветки правил с двумя допустимыми значениями и SHALL использовать значение по умолчанию, когда параметр не передан. Аргумент, не удовлетворяющий схеме (отсутствует обязательный параметр, пустое значение, недопустимая ветка правил, лимит вне диапазона), SHALL отклоняться результатом с понятным текстом и SHALL NOT приводить к обращению к внешнему API. Неизвестный раздел SHALL отклоняться результатом, перечисляющим разделы, которые объявляет сам внешний API, и SHALL NOT приводить к запросу записей этого раздела.

#### Scenario: Схема параметров видна клиенту
- **WHEN** клиент запрашивает список инструментов собственного сервера
- **THEN** каждый инструмент несёт схему входных параметров с их именами, типами и признаком обязательности

#### Scenario: Ветка правил по умолчанию
- **WHEN** инструмент вызван без параметра ветки правил
- **THEN** запрос к внешнему API уходит с веткой правил по умолчанию

#### Scenario: Ветка правил задана явно
- **WHEN** инструмент вызван со второй допустимой веткой правил
- **THEN** запрос к внешнему API уходит с указанной веткой

#### Scenario: Обязательный параметр не передан
- **WHEN** инструмент вызван без обязательного параметра
- **THEN** результат вызова несёт текст об отсутствующем параметре, а обращения к внешнему API не происходит

#### Scenario: Недопустимая ветка правил
- **WHEN** инструмент вызван с веткой правил, которой нет среди допустимых
- **THEN** результат вызова несёт текст с допустимыми значениями, а обращения к внешнему API не происходит

#### Scenario: Неизвестный раздел
- **WHEN** инструмент вызван с разделом, которого внешний API не объявляет
- **THEN** результат вызова перечисляет доступные разделы, а записи этого раздела не запрашиваются

### Requirement: Вызов инструмента MCP и снимок результата
Агент SHALL уметь вызвать названный инструмент названного сервера реестра с набором аргументов. Соединение для вызова SHALL подниматься по требованию и закрываться после получения результата, не оставляя запущенных процессов. Результат вызова SHALL отдаваться снимком, содержащим имя сервера, имя инструмента, переданные аргументы, текст результата и текст ошибки, если вызов не удался. Неизвестное имя сервера, неизвестное имя инструмента, отказ запуска сервера и ошибка самого инструмента SHALL попадать в поле ошибки снимка и SHALL NOT прерывать сессию. Вызов инструмента SHALL NOT обращаться к языковой модели сам по себе. Терминальный слой SHALL рисовать результат только по снимку и SHALL NOT обращаться к клиенту соединения напрямую.

#### Scenario: Инструмент вызван успешно
- **WHEN** агент вызывает существующий инструмент существующего сервера с допустимыми аргументами
- **THEN** снимок содержит имя сервера, имя инструмента, аргументы и текст результата, а поле ошибки пусто

#### Scenario: Процесс сервера не остаётся висеть после вызова
- **WHEN** вызов инструмента завершён
- **THEN** серверный процесс остановлен

#### Scenario: Неизвестный инструмент
- **WHEN** запрошен инструмент, которого сервер не объявлял
- **THEN** снимок несёт текст ошибки, а сессия продолжается

#### Scenario: Неизвестный сервер
- **WHEN** запрошен сервер, которого нет в реестре
- **THEN** снимок несёт текст ошибки с именем запрошенного сервера, и ни один процесс не запускается

#### Scenario: Сервер недоступен при вызове
- **WHEN** серверный процесс не запускается или не отвечает по протоколу
- **THEN** снимок несёт текст ошибки, а диалог и его история остаются нетронутыми

#### Scenario: Вызов инструмента сам по себе не тратит токены
- **WHEN** агент вызывает инструмент по явному указанию пользователя
- **THEN** ни один запрос к языковой модели не отправляется и счётчики токенов сессии не меняются

### Requirement: Автоматический выбор инструмента перед вопросом
При включённом автоматическом режиме агент SHALL перед отправкой вопроса выполнять отдельный запрос к модели, в котором перечислены доступные инструменты с их описаниями и входными параметрами, и SHALL разбирать ответ модели на стороне приложения, без опоры на формат ответа, навязанный API. Выбранный инструмент SHALL вызываться с выбранными аргументами. Ответ модели, означающий «инструмент не нужен», SHALL быть допустимым исходом и SHALL NOT считаться сбоем. Сбой выбора (ошибка запроса, пустой или неразбираемый ответ, неизвестное имя инструмента) и сбой самого вызова SHALL NOT блокировать ответ на вопрос: вопрос SHALL уходить без результата инструмента. Расход вспомогательного запроса SHALL попадать в счётчики сессии. При выключенном автоматическом режиме вспомогательный запрос SHALL NOT отправляться вовсе.

#### Scenario: Модель выбирает инструмент
- **WHEN** пользователь задаёт вопрос, для которого модель выбирает инструмент и аргументы
- **THEN** инструмент вызывается с этими аргументами до отправки вопроса

#### Scenario: Инструмент не нужен
- **WHEN** модель отвечает, что подходящего инструмента нет
- **THEN** вопрос уходит без вызова инструмента и без сообщения об ошибке

#### Scenario: Выбор не удался
- **WHEN** запрос выбора завершается ошибкой или ответ невозможно разобрать
- **THEN** пользователь получает ответ на свой вопрос, а сведения о неудавшемся выборе доступны вызывающей стороне

#### Scenario: Вызов выбранного инструмента не удался
- **WHEN** выбранный инструмент возвращает ошибку или сервер недоступен
- **THEN** пользователь получает ответ на свой вопрос, а сведения о неудавшемся вызове доступны вызывающей стороне

#### Scenario: Автоматический режим выключен
- **WHEN** автоматический режим выключен и пользователь задаёт вопрос
- **THEN** вспомогательный запрос выбора не отправляется и ни один инструмент не вызывается

#### Scenario: Расход вспомогательного запроса учтён
- **WHEN** выполнен запрос выбора инструмента
- **THEN** его токены и стоимость попадают в счётчики сессии

### Requirement: Результат инструмента в запросе к модели
Успешный результат вызова инструмента SHALL уходить в запрос к модели отдельным системным сообщением, расположенным выше сообщений диалога, вместе с указанием, что это данные внешнего источника, полученные для текущего вопроса. Результат SHALL NOT записываться в файл истории диалога и SHALL NOT восстанавливаться при следующем запуске. Когда инструмент не вызывался или вызов не удался, состав сообщений запроса SHALL оставаться прежним.

#### Scenario: Результат попадает в запрос
- **WHEN** инструмент вызван успешно перед вопросом
- **THEN** запрос к модели содержит отдельное системное сообщение с результатом инструмента выше сообщений диалога

#### Scenario: Без вызова состав сообщений прежний
- **WHEN** инструмент не вызывался или вызов не удался
- **THEN** запрос к модели не содержит сообщения с результатом инструмента

#### Scenario: Результат не попадает в историю
- **WHEN** обмен с вызовом инструмента завершён
- **THEN** в файле истории сохранены только вопрос и ответ, без результата инструмента
