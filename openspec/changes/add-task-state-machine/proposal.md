# Change: Состояние задачи — конечный автомат Planning → Execution → Validation → Done

## Why
Агент помнит диалог, память и профиль, но не ведёт работу: формализованного состояния задачи у него нет, поэтому
этапы не различаются, а после паузы — тем более после перезапуска — пользователь заново объясняет, что делается и
что уже сделано. Задача дня 13 — состояние задачи как конечный автомат: этап, текущий шаг, ожидаемое действие,
самостоятельные переходы агента между этапами и задачами; пользователю остаются пауза и продолжение.

## What Changes
- Вводится **конечный автомат задачи** с четырьмя этапами: **Planning** (план подзадач, затем вопрос о правках:
  правки есть → Planning заново с ними, правок нет → дальше), **Execution** (выполнение подзадач по одной, без
  участия пользователя), **Validation** (детерминированные проверки артефакта плюс ревью модели), **Done** (итог и
  краткое summary пользователю). Переходы делает агент — и от этапа к этапу, и от задачи к задаче.
- Пользователь входит в работу **очередью**: `/task add <цель>` ставит задачу, `/task run` запускает прогон, в
  котором агент ведёт задачи одну за другой. Единственное управление во время прогона — **пауза** (клавиша `p` или
  Ctrl+C) и продолжение тем же `/task run`; `/task` показывает состояние, `/task stop` снимает очередь, когда
  конвейер не идёт.
- **Состояние обновляется постоянно и переживает всё**: этап, текущий шаг (круг плана / подзадача k из N / попытка
  проверки), ожидаемое действие, план подзадач, артефакт по разделам, замечания проверки и признак паузы живут в
  своём файле `task.json` и пишутся на диск до каждого следующего запроса — пауза, Ctrl+C и выход приложения ничего
  не теряют, `/task run` продолжает ровно с сохранённого шага.
- **Состояние видно**: живая панель на время прогона (этапы с отметкой текущего, текущий шаг, ожидаемое действие,
  план с отметками), отчёт `/task` без обращений к модели (очередь со статусами, этап, план, артефакт, замечания,
  путь файла) и строка статус-бара. В журнал попадают строка паузы, summary этапа Done, вопрос о правках и обычные
  строки метрик `⏱` — панель закрывается вместе с прогоном.
- **План задач и результат строит модель**: план подзадач — отдельный запрос Planning, каждая подзадача — запрос
  Execution, дописывающий раздел артефакта, вердикт проверки — запрос Validation. Ответы разбираются клиентской
  стороной (JSON плана и вердикта), как у извлекателя фактов, без `response_format`.
- **Сбой не останавливает конвейер**: упавший запрос повторяется, затем подзадача помечается невыполненной, задача —
  `failed`, и агент берёт следующую из очереди; недоступное ревью модели не отменяет детерминированных проверок.
- `/clear` очередь задач не трогает: задача — не диалог, как и профиль с долговременной памятью.
- Новые настройки: переключатель `TABLETOP_TASK_FILE` и границы конвейера (число подзадач плана, круги Planning,
  попытки Validation, объём запроса задачи, предел длины цели).

## Capabilities

### New Capabilities
- `task-state`: конечный автомат задачи — очередь задач, четыре этапа с их переходами и кругами правок, поля
  «этап», «текущий шаг», «ожидаемое действие», план подзадач и артефакт, пауза и продолжение, хранилище `task.json`,
  самостоятельные запросы Planning/Execution/Validation, отчёт и живая панель для интерфейса.

### Modified Capabilities
- `terminal-ui`: «Команды приложения и их распознавание» — появляется команда `/task` со значимыми аргументами; новые
  требования «Отчёт команды /task», «Прогон конвейера задачи и пауза в терминале» и «Строка задачи в статус-баре».
- `agent`: «Стек сообщений сессии» — в обычный вопрос добавляется системное сообщение состояния задачи; «Сброс
  контекста» — `/clear` SHALL NOT трогать очередь задач; «Ошибки API отдаются вызывающей стороне» — сбой запроса
  конвейера задача не роняет, а помечает её `failed`.
- `configuration`: «Переменные переопределения поведения» — добавляется `TABLETOP_TASK_FILE`; «Поведенческие
  константы» — границы конвейера (подзадачи плана, круги Planning, попытки Validation, объём запроса задачи, предел
  длины цели).
- `test-infrastructure`: «Изоляция окружения тестов» — новый файл состояния (очередь задач) под переопределением,
  как история, долговременная память и профиль.

## Impact
Код: новые `core/task_state.py` (состояние, переходы, хранилище, сборка сообщения) и `core/task_pipeline.py`
(шаговый исполнитель конвейера), новые ассеты `assets/task_plan_prompt.md`, `assets/task_execute_prompt.md`,
`assets/task_validate_prompt.md`, `assets/task_prompt.md`, правки `core/config.py`, `core/tabletop_agent.py`
(владение состоянием и конвейером, новые фазы запроса, снимок для интерфейса, сообщение в стеке), `ui/keyboard.py`
(неблокирующее чтение клавиши), `ui/tui_app.py` (команда `/task`, цикл прогона, панель, статус-бар),
`ui/commands_screen.py` (список команд), `.gitignore` (`task.json`).
Тесты: новые `tests/unit/test_task_state.py`, `tests/unit/test_task_pipeline.py`, `tests/e2e/test_task_flow.py`;
правки `tests/unit/test_tabletop_agent.py`, `tests/unit/test_tui_app.py`, `tests/unit/test_keyboard.py`,
`tests/unit/test_config.py`, `tests/e2e/harness.py` (изоляция файла задач), снапшоты панели `/commands`.
Документация: `README.md`, `CLAUDE.md`.
Внешний API запросов не меняется: конвейер пользуется тем же `chat/completions`, добавляя прижатый `max_tokens` и
свои системные сообщения.

## Критерии приёмки (день 13, дословно из задания)

Задача:
- этап задачи
- текущий шаг
- ожидаемое действие

Пример состояний: planning → execution → validation → done.

Проверьте:
- паузу на любом этапе
- продолжение без повторных объяснений

Результат: агент с формализованным состоянием задачи.

Шаги демонстрации (каждый пункт — то, что видно в записи):
1. Прогон без паузы: `/task` на пустой очереди, затем две задачи через `/task add` и `/task run` — Planning с
   планом и вопросом о правках, повторный Planning после правок, Execution по шагам, Validation, Done с summary и
   самостоятельный переход ко второй задаче; панель показывает этапы, текущий шаг и ожидаемое действие, очередь
   заканчивается сама.
2. `/task` после прогона: обе задачи решены, у каждой артефакт с разделами и объёмом.
3. Прогон с паузой: третья задача, пауза клавишей `p` на шаге Execution → строка паузы, панель закрывается.
4. `/task` на паузе: этап, текущий шаг и ожидаемое действие ровно там, где остановились.
5. `/task run` после паузы: работа продолжается с того же шага, без повторных объяснений, до Validation и Done.
