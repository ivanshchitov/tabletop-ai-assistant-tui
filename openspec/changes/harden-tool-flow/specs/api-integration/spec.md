## MODIFIED Requirements

### Requirement: Политика повторов
При таймауте запроса клиент SHALL повторять попытку до 3 раз включительно с экспоненциальной паузой между попытками; после исчерпания — понятное сообщение о превышении времени ожидания. Ответ со статусом 502, 503 или 504 (временная недоступность сервиса) SHALL повторяться так же, как таймаут, а после исчерпания попыток SHALL превращаться в сообщение об ошибке API со статусом. При ошибке соединения повторы SHALL NOT выполняться (персистентная сетевая проблема, а не переходный сбой): сразу сообщение о проверке интернет-соединения.

#### Scenario: Один таймаут и успех
- **WHEN** первая попытка истекает по таймауту, вторая завершается ответом
- **THEN** пользователь получает ответ, всего выполнено 2 попытки

#### Scenario: Все попытки истекли
- **WHEN** все 3 попытки истекают по таймауту
- **THEN** пользователь видит сообщение о превышении времени ожидания

#### Scenario: Ошибка соединения без повторов
- **WHEN** сервер недоступен (ошибка соединения)
- **THEN** выполняется ровно одна попытка, пользователь видит сообщение о соединении

#### Scenario: Временная недоступность сервиса и успех
- **WHEN** первая попытка получает ответ 503, вторая завершается ответом
- **THEN** пользователь получает ответ, всего выполнено 2 попытки

#### Scenario: Сервис недоступен на всех попытках
- **WHEN** все 3 попытки получают ответ 503
- **THEN** пользователь видит сообщение об ошибке API со статусом 503
