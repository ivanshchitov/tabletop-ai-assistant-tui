# Change: Стратегии управления контекстом (вместо сжатия-монополиста)

## Why
Управление контекстом в агенте одно: старейшие ходы сворачиваются моделью в резюме, выключателя нет, а ходы
при сжатии теряются из стека. Задача дня 10 — дать минимум три стратегии управления контекстом и переключатель
между ними, чтобы сравнивать качество, стабильность и расход токенов на одном сценарии. Заодно убирается
команда `/logictask`: она осталась демонстрацией дня 6, держит в агенте второй путь запроса к модели и мешает
переработать контекст.

## What Changes
- Стратегия управления контекстом становится настройкой сессии рядом с форматом ответа: `summary` (сжатое
  резюме, по умолчанию — поведение дня 9), `sliding_window` (окно последних N сообщений), `sticky_facts` (блок
  фактов «ключ — значение» плюс окно), `branching` (ходы активной ветки диалога). Выбор — на экране `/settings`
  и в статус-баре.
- **BREAKING** — ходы больше не удаляются из стека при сжатии: стек сессии append-only, стратегия решает только,
  какие ходы попадут в запрос. Переключение стратегии ничего не теряет.
- Сжатие истории остаётся, но как стратегия `summary` и значение по умолчанию: порог сжатия и потолок токенов
  работают как раньше, только свёрнутые ходы остаются в стеке, а не выбрасываются.
- Стратегия `sticky_facts`: перед каждым вопросом отдельный запрос к модели обновляет блок фактов из сообщений
  пользователя; в запрос вопроса уходят блок фактов и последние N сообщений. Сбой обновления не мешает ответу.
- Стратегия `branching`: чекпоинт и ветки диалога в пределах сессии, переключение ветки меняет состав запросов.
- Новая команда `/context` — отчёт о состоянии контекста без запросов к модели: стратегия, окно, факты, ветки,
  приближённая оценка токенов против потолка. Отчёт строит агент, интерфейс только рендерит — агент остаётся
  изолированной сущностью.
- Новая панель `/branches` (редьюсер, как у `/settings`): выбор ветки, новая ветка от чекпоинта, чекпоинт.
- **BREAKING** — команда `/logictask` удаляется целиком: панель выбора стратегии промптинга, фиксированная задача,
  четыре техники и строка метрик под каждым запросом прогона; capability `prompt-strategies` уходит из спеки.
  Ввод `/logictask` становится обычным вопросом, как любой неизвестный ввод с `/`.
- Файл истории: конверт дополняется блоком `facts`; резюме остаётся; ветки в файл не пишутся (плоский список
  обменов).

## Capabilities

### New Capabilities
- `context-strategies`: выбор стратегии управления контекстом сессии, её переключаемость без потерь, правила
  каждой стратегии (окно, факты, ветки), учёт расхода вспомогательных запросов и снимок состояния контекста для
  интерфейса.

### Modified Capabilities
- `agent`: «Стек сообщений сессии» — append-only стек, состав запроса задаёт стратегия; «Сжатое резюме как
  отдельная память агента» — резюме принадлежит стратегии `summary` и сохраняется при переключении; «Потолок
  контекста сессии» — инвариант для всех стратегий (окно сужается, факты не сокращаются, последний обмен цел);
  «Восстановление стека из сохранённой истории» — догоняющая суммаризация только при стратегии `summary`;
  требование «Решение логической задачи» удаляется.
- `answer-settings`: шесть настроек становятся семью — добавляется стратегия контекста (`summary` по умолчанию),
  снимок настроек остаётся неизменяемым, невалидное значение — ошибка без клампинга.
- `settings-screen`: семь полей, строка выбора стратегии стрелками, цикл навигации по семи строкам.
- `terminal-ui`: команды `/context` и `/branches` в списке приложения (список перечисляется заново, без удалённой
  команды), стратегия в статус-баре, фаза «Обновление фактов...» в индикаторе, строка о неудачном обновлении
  фактов, отчёт `/context`; из `/usage` уходит состояние окна контекста (его показывает `/context`).
- `history-persistence`: конверт с блоком `facts`, очистка опустошает и факты, реплей восстанавливает и их.
- `configuration`: поведенческие константы — список стратегий с дефолтом, потолок объёма блока фактов, предел
  числа ключей фактов.
- `question-answering`: контекст сессии в ответах собирается по активной стратегии, а не только резюме и хвостом.
- `api-integration`: форма запроса — system настроек, контекст активной стратегии (при фактах — отдельное
  системное сообщение с блоком), новый user-ход; глубина контекста задаётся стратегией и потолком, а не потолком
  числа записей истории (`HISTORY_LIMIT` упоминался в тексте, хотя удалён ещё днём 9).
- `model-selection`: модель сессии применяется ко всем запросам к API — и на вопрос, и на вспомогательные запросы
  стратегии; сценарий прогона уходит вместе с командой.
- `prompt-strategies`: capability удаляется целиком вместе с командой прогонов.

## Impact
Код: новый `core/context_strategies.py` (окно, факты, ветки — чистые структуры и сборка), правки
`core/tabletop_agent.py` (стратегия в конфиге, цикл выбора состава запроса, память стратегий, снимок контекста),
`core/answer_settings.py`, `core/history_manager.py` (поле `facts`), `core/config.py`, новый ассет
`assets/facts_prompt.md`, `ui/settings_screen.py` (седьмая строка), `ui/branches_screen.py` (новый редьюсер),
`ui/commands_screen.py`, `ui/tui_app.py`, `ui/keyboard.py` (докстринг). Удаляются `core/logictask.py`,
`ui/logictask_screen.py`. Тесты: новые `tests/unit/test_context_strategies.py`, `test_branches_screen.py`; правки
`test_tabletop_agent.py`, `test_answer_settings.py`, `test_settings_screen.py`, `test_tui_app.py`,
`test_history_manager.py`, `test_config.py`; e2e — новые сценарии стратегий и панели веток, правки
`test_agent_context.py`, снапшоты экранов; удаляются `tests/unit/test_logictask.py`,
`tests/unit/test_logictask_screen.py`, `tests/e2e/test_strategies.py`. Документация: `README.md`, `CLAUDE.md`.
Внешний API не меняется; в теле запроса появляется второе системное сообщение только при стратегии фактов.
