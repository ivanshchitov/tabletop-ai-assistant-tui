## Purpose

Цепочка MCP-инструментов за один вопрос: агент сам проходит шаги «получить данные → обработать → сохранить результат», передавая результат одного шага на вход следующего без искажений, а собственный сервер проекта предоставляет для этого инструменты сводки и сохранения в файл.

## ADDED Requirements

### Requirement: Цепочка шагов из одного запроса выбора
Автоматический выбор инструмента SHALL уметь вернуть упорядоченную цепочку шагов, каждый из которых называет инструмент и его аргументы, и агент SHALL выполнить шаги по порядку без участия пользователя. Вся цепочка SHALL выбираться одним вспомогательным запросом к модели; выполнение шагов SHALL NOT порождать новых запросов выбора. Ответ, называющий единственный инструмент в прежнем формате, SHALL трактоваться как цепочка из одного шага. Число выполняемых шагов SHALL ограничиваться потолком из конфигурации (4); шаги сверх потолка SHALL NOT выполняться, а отбрасывание SHALL быть видно вызывающей стороне.

#### Scenario: Цепочка из трёх шагов выполняется автоматически
- **WHEN** модель в ответ на запрос выбора возвращает цепочку из трёх шагов
- **THEN** три инструмента вызываются по порядку до отправки вопроса, а к модели уходит ровно один запрос выбора

#### Scenario: Прежний формат с одним инструментом
- **WHEN** модель возвращает один инструмент в прежнем формате
- **THEN** он выполняется как цепочка из одного шага

#### Scenario: Цепочка длиннее потолка
- **WHEN** модель возвращает больше шагов, чем разрешает потолок
- **THEN** выполняются только первые шаги в пределах потолка, а сведения об отброшенных доступны вызывающей стороне

### Requirement: Передача данных между шагами по ссылке
Строковый аргумент шага, значение которого целиком равно ссылке `$N`, где N — номер уже выполненного шага цепочки (с единицы), SHALL заменяться полным текстом результата шага N до вызова инструмента — дословно, без усечения и без пересказа моделью. Ссылка на шаг, который ещё не выполнен или не существует, SHALL делать шаг ошибочным и SHALL NOT приводить к вызову инструмента. Значения, лишь содержащие ссылку внутри другого текста, SHALL передаваться как есть.

#### Scenario: Результат шага 1 доходит до шага 2 дословно
- **WHEN** аргумент второго шага равен `$1`
- **THEN** инструмент второго шага получает в этом аргументе ровно текст результата первого шага

#### Scenario: Ссылка вперёд
- **WHEN** аргумент шага ссылается на шаг с тем же или большим номером
- **THEN** шаг завершается ошибкой без вызова инструмента, и цепочка останавливается

### Requirement: Сбой шага останавливает цепочку
Если шаг цепочки завершился ошибкой (неизвестный сервер или инструмент, недоступный сервер, отказ самого инструмента, неверная ссылка), следующие шаги SHALL NOT выполняться, а текст ошибки SHALL NOT передаваться следующему инструменту как данные. Сбой цепочки SHALL NOT блокировать ответ на вопрос: в запрос к модели SHALL уходить результаты шагов, выполненных успешно до сбоя.

#### Scenario: Отказ второго шага
- **WHEN** второй шаг цепочки из трёх возвращает ошибку
- **THEN** третий шаг не вызывается, пользователь получает ответ на вопрос, а в запросе к модели есть результат только первого шага

### Requirement: Журнал шагов цепочки
Терминальный слой SHALL печатать по строке журнала на каждый выполненный шаг: номер шага из общего числа, имя инструмента, аргументы, полученные по ссылке, с номером шага-источника и объёмом переданного текста в символах, и объём результата шага. Неудачный шаг SHALL печатать причину. Строки журнала SHALL быть только экранными и SHALL NOT попадать в файл истории.

#### Scenario: Объём передачи виден в журнале
- **WHEN** выполнена цепочка, в которой шаг 2 получает `$1`
- **THEN** строка шага 2 называет шаг-источник 1 и объём, равный объёму результата шага 1 в строке шага 1

### Requirement: Сводка результата поиска
Собственный сервер проекта SHALL предоставлять инструмент сводки, принимающий текст (результат другого инструмента) и необязательный предел числа пунктов. Сводка SHALL строиться детерминированно, без обращения к языковой модели и к внешнему API: по одной строке на запись с названием, ключевыми полями записи и первым предложением описания. Поиск SHALL принимать необязательный параметр подробностей; с ним результат поиска SHALL содержать основные поля каждой найденной записи в машиночитаемом виде. Текст без распознаваемых записей SHALL отклоняться результатом-ошибкой с объяснением.

#### Scenario: Сводка подробного поиска
- **WHEN** на вход сводки подан результат поиска с подробностями по трём записям
- **THEN** сводка содержит три строки с названиями этих записей

#### Scenario: Текст без записей
- **WHEN** на вход сводки подан текст без распознаваемых записей
- **THEN** вызов завершается ошибкой с объяснением

### Requirement: Сохранение результата в файл
Собственный сервер проекта SHALL предоставлять инструмент сохранения, записывающий переданный текст в markdown-файл каталога выгрузок под переданным именем и возвращающий путь к файлу и число сохранённых символов. Каталог выгрузок SHALL задаваться переменной окружения `TABLETOP_EXPORTS_DIR` (по умолчанию `exports/` в корне репозитория) и SHALL передаваться серверному процессу. Имя, выводящее путь за пределы каталога (абсолютный путь, `..`, разделители каталогов), SHALL отклоняться. Существующий файл SHALL NOT перезаписываться: новый файл получает числовой суффикс. Пустой текст SHALL отклоняться.

#### Scenario: Текст сохранён
- **WHEN** вызвано сохранение с текстом и именем `fire-spells`
- **THEN** в каталоге выгрузок появляется `fire-spells.md` с этим текстом, а результат называет путь и число символов

#### Scenario: Попытка выйти за каталог
- **WHEN** имя файла содержит `..` или разделитель каталогов
- **THEN** вызов завершается ошибкой, и ни один файл не пишется

#### Scenario: Файл уже существует
- **WHEN** файл с таким именем уже есть в каталоге выгрузок
- **THEN** прежний файл не меняется, а текст сохраняется в файл с суффиксом

#### Scenario: Каталог переопределён
- **WHEN** задана `TABLETOP_EXPORTS_DIR`
- **THEN** файл пишется в указанный каталог, а каталог по умолчанию не трогается
