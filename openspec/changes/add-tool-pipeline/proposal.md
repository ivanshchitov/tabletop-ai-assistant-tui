## Why

День 19 челленджа — композиция MCP-инструментов: search → summarize → saveToFile, где первый инструмент получает данные, второй их обрабатывает, третий сохраняет результат, а цепочка выполняется автоматически и передаёт данные между шагами без искажений. Сейчас агент за один вопрос вызывает не больше одного инструмента, а собственный сервер умеет только добывать справочные данные — ни обработать их, ни сохранить он не может.

## What Changes

- Собственный сервер `dnd-rules` (новых серверов нет) получает два инструмента: сводку (`dnd_summarize`) — детерминированную выжимку из результата поиска, и сохранение в файл (`save_to_file`) — запись текста в markdown-файл каталога выгрузок.
- Поиск (`dnd_search`) получает необязательный параметр подробностей: с ним он отдаёт не только имена, а основные поля найденных записей в машиночитаемом виде — это вход для сводки.
- Каталог выгрузок задаётся переменной `TABLETOP_EXPORTS_DIR` (по умолчанию `exports/` в корне репозитория, в `.gitignore`); путь к файлу не выходит за его пределы, существующий файл не перезаписывается.
- Неудачный вызов любого инструмента собственного сервера помечается протокольным признаком ошибки, а не только текстом — клиент отличает отказ от данных.
- Автоматический выбор инструмента возвращает **цепочку** шагов одним запросом выбора; прежний ответ с одним инструментом остаётся допустимым как цепочка из одного шага. Аргумент шага, равный ссылке `$N`, агент заменяет полным текстом результата шага N. Длина цепочки ограничена (`TOOL_CHAIN_MAX_STEPS`, 4); сбой шага останавливает цепочку.
- Модель, отвечающая на вопрос, получает результаты всех выполненных шагов; журнал печатает строку на каждый шаг — с тем, откуда пришли данные и сколько символов передано.

## Критерии приёмки

Дословно из задачи дня 19:
- «Реализуйте пайплайн: первый инструмент получает данные, второй — обрабатывает, третий — сохраняет результат».
- «Проверьте: автоматическое выполнение цепочки».
- «Проверьте: корректность передачи данных между инструментами».
- «Результат: Автоматический пайплайн из нескольких MCP-инструментов».

Шаги демо:
1. Приложение запущено, автоматический вызов инструментов включён.
2. На вопрос «Найди заклинания огня D&D, сделай краткую сводку и сохрани её в файл fire-spells» журнал показывает три шага `🔧 1/3 … 3/3`; вход шага 2 равен выходу шага 1, объём сохранённого равен выходу шага 2; модель отвечает с путём к файлу.
3. После выхода из приложения `exports/fire-spells.md` содержит ту же сводку.

## Capabilities

### New Capabilities
- `tool-pipeline`: цепочка инструментов за один вопрос — план шагов, ссылки на результаты прошлых шагов, остановка на сбое, инструменты сводки и сохранения в файл, каталог выгрузок.

### Modified Capabilities
- `mcp-integration`: собственный сервер объявляет инструменты сводки и сохранения и помечает отказы признаком ошибки; автоматический выбор возвращает цепочку шагов; в запрос уходят результаты всех шагов.
