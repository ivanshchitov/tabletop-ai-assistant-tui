# Design: отрицательное упоминание запрещённого слова

## Context
`core/invariants.check_answer` — подстрочная регистронезависимая проверка по основам слов (`design.md` изменения
`add-agent-invariants`, D4). Модель, соблюдая правило, называет запрещённое в отрицании («без приложений»), и
проверка считает это нарушением.

## Goals / Non-Goals
**Goals:** не считать нарушением вхождение слова в отрицании; оставить нарушением вхождение без отрицания.
**Non-Goals:** морфология и разбор предложений; правка промпта (решение пользователя: только код).

## Decisions
**D1 — окно отрицания перед словом.** Для каждого вхождения основы берутся `NEGATION_WINDOW` (20) символов
перед ним; если там есть маркер из `NEGATIONS` («без», «не», «нет», «никаких», «ни», «запрещ», «отсутств») как
начало слова — вхождение пропускается. Нарушение — первое вхождение без отрицания. Эвристика, а не грамматика:
«нельзя без смартфона» пропустится ложно, «обязательно приложение» поймается. Цена ошибки в обе стороны — один
запрос или один пропуск, промпт остаётся первой линией защиты.

## Risks / Trade-offs
- [Пропуск нарушения в обороте с отрицанием] → промпт по-прежнему запрещает предлагать запрещённое; окно узкое.
