## MODIFIED Requirements

### Requirement: Реестр описаний MCP-серверов
Приложение SHALL хранить список описаний MCP-серверов, каждое из которых содержит имя, транспорт, команду запуска, аргументы команды, имена переменных окружения с секретами сервера и краткое описание. Один сервер SHALL быть выбран как используемый по умолчанию. Подключение SHALL опираться только на описание: ни имена инструментов, ни их схемы, ни адрес источника данных SHALL NOT задаваться в коде приложения. Добавление или замена сервера SHALL требовать только новой записи реестра. Переопределение команды запуска через окружение SHALL заменять **весь** реестр: иначе автоматический прогон поднимал бы все настоящие серверы реестра. Переопределение SHALL давать одну запись, а когда аргументы команды перечисляют несколько наборов через ` | `, — по записи на каждый набор с той же командой и различимыми именами.

#### Scenario: Сервер по умолчанию задан описанием
- **WHEN** пользователь запрашивает подключение, не указывая сервер
- **THEN** соединение поднимается по описанию сервера, выбранного по умолчанию

#### Scenario: Секреты сервера берутся из окружения
- **WHEN** описание сервера называет переменные окружения с секретами и они заданы в окружении
- **THEN** их значения передаются запускаемому серверу, а отсутствующие переменные просто не передаются

#### Scenario: Имена инструментов не зашиты в приложение
- **WHEN** описание сервера заменено на другой сервер с другим набором инструментов
- **THEN** приложение подключается и показывает новый набор без правки кода

#### Scenario: Переопределение окружением заменяет весь реестр
- **WHEN** задана переменная с командой запуска сервера
- **THEN** реестр для этого запуска состоит ровно из одной записи — заданной окружением, а записи по умолчанию не используются

#### Scenario: Переопределение окружением с несколькими серверами
- **WHEN** аргументы переопределённой команды перечисляют два набора через ` | `
- **THEN** реестр для этого запуска состоит из двух записей с различными именами, каждая со своим набором аргументов

### Requirement: Автоматический выбор инструмента перед вопросом
При включённом автоматическом режиме агент SHALL перед отправкой вопроса выполнять отдельный запрос к модели, в котором перечислены доступные инструменты с их описаниями и входными параметрами, и SHALL разбирать ответ модели на стороне приложения, без опоры на формат ответа, навязанный API. Ответ выбора SHALL называть один инструмент или цепочку шагов; выбранные инструменты SHALL вызываться с выбранными аргументами по порядку. Ответ может пометить, что нужен следующий раунд выбора, — тогда на один вопрос уходит несколько запросов выбора, по одному на раунд, в пределах конфигурации. Ответ модели, означающий «инструмент не нужен», SHALL быть допустимым исходом и SHALL NOT считаться сбоем. Сбой выбора (ошибка запроса, пустой или неразбираемый ответ, неизвестное имя инструмента) и сбой самого вызова SHALL NOT блокировать ответ на вопрос: вопрос SHALL уходить без результата инструмента. Расход каждого вспомогательного запроса SHALL попадать в счётчики сессии. При выключенном автоматическом режиме вспомогательный запрос SHALL NOT отправляться вовсе. Начальное состояние режима SHALL браться из конфигурации приложения, а переключение в течение сессии SHALL действовать до её конца.

#### Scenario: Модель выбирает инструмент
- **WHEN** пользователь задаёт вопрос, для которого модель выбирает инструмент и аргументы
- **THEN** инструмент вызывается с этими аргументами до отправки вопроса

#### Scenario: Инструмент не нужен
- **WHEN** модель отвечает, что подходящего инструмента нет
- **THEN** вопрос уходит без вызова инструмента и без сообщения об ошибке

#### Scenario: Выбор не удался
- **WHEN** запрос выбора завершается ошибкой или ответ невозможно разобрать
- **THEN** пользователь получает ответ на свой вопрос, а сведения о неудавшемся выборе доступны вызывающей стороне

#### Scenario: Вызов выбранного инструмента не удался
- **WHEN** выбранный инструмент возвращает ошибку или сервер недоступен
- **THEN** пользователь получает ответ на свой вопрос, а сведения о неудавшемся вызове доступны вызывающей стороне

#### Scenario: Автоматический режим выключен
- **WHEN** автоматический режим выключен и пользователь задаёт вопрос
- **THEN** вспомогательный запрос выбора не отправляется и ни один инструмент не вызывается

#### Scenario: Расход вспомогательного запроса учтён
- **WHEN** выполнен запрос выбора инструмента
- **THEN** его токены и стоимость попадают в счётчики сессии

#### Scenario: Модель выбирает цепочку
- **WHEN** модель в ответ на запрос выбора возвращает цепочку шагов без пометки о следующем раунде
- **THEN** шаги выполняются по порядку до отправки вопроса без дополнительных запросов выбора

#### Scenario: Модель просит следующий раунд
- **WHEN** модель возвращает шаги с пометкой о следующем раунде
- **THEN** после их выполнения уходит ещё один запрос выбора, и его расход тоже попадает в счётчики сессии
