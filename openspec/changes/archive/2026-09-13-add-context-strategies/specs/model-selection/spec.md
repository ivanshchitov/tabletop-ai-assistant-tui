## REMOVED Requirements

### Requirement: Выбранная модель применяется ко всем запросам сессии
**Reason**: Требование называло прогоны `/logictask` вторым видом запросов; прогоны удаляются, и формулировка
без них — отдельное требование (см. «Модель сессии применяется ко всем запросам к API»).
**Migration**: Поведение переносится без изменений: модель сессии применяется ко всем запросам к API, по
умолчанию `deepseek-v4-flash`, выбор не переживает перезапуск.

## ADDED Requirements

### Requirement: Модель сессии применяется ко всем запросам к API
Выбранная через `/models` модель SHALL использоваться во всех запросах к API до конца сессии: как при ответе на
вопрос, так и во вспомогательных запросах активной стратегии управления контекстом (обновление фактов,
суммаризатор). До явного выбора SHALL использоваться модель `deepseek-v4-flash`. Выбор SHALL действовать только
в рамках сессии: после перезапуска приложения активна модель по умолчанию, выбор не сохраняется.

#### Scenario: Вопрос после смены модели
- **WHEN** пользователь выбрал `glm-5.1` и задаёт вопрос
- **THEN** запрос к API содержит модель `glm-5.1`

#### Scenario: Вспомогательный запрос стратегии следует выбору
- **WHEN** пользователь выбрал `kimi-k2.5`, активна стратегия фактов и он задаёт вопрос
- **THEN** и запрос обновления фактов, и запрос вопроса уходят с моделью `kimi-k2.5`

#### Scenario: Выбор не переживает перезапуск
- **WHEN** пользователь выбрал `mimo-v2.5-free`, завершил приложение и запустил снова
- **THEN** активна модель по умолчанию `deepseek-v4-flash`
