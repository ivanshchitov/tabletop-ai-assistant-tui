## Why

Задача дня 7 челленджа («Сохранение контекста») требует, чтобы агент при перезапуске
продолжал диалог так, как будто не выключался: история сообщений сохраняется на диск,
загружается обратно и участвует в запросах к модели. Сейчас история при старте только
показывается на экране — стек сообщений агента всегда начинается пустым, и первый вопрос
после рестарта уходит в модель без прошлой переписки. Это зафиксировано в спеке
`history-persistence` как осознанное решение дня 6; день 7 переворачивает его.

## What Changes

- `TabletopAgent` получает метод `restore_context(dialogues)`: пары «вопрос–ответ» из
  `HistoryManager` превращаются в ходы user/assistant стека с тем же потолком
  `HISTORY_LIMIT` обменов.
  - user-ход пересобирается через `build_user_prompt(question, settings)` с текущими
    настройками (в `history.json` хранится голый вопрос, не промпт); ответ — дословно.
  - Формат `history.json` не меняется; существующие файлы истории подхватываются как есть.
- `TabletopAITUI` при старте после реплея истории засеивает стек агента из тех же
  `history.dialogues` — реплей на экране и контекст модели всегда согласованы.
- `/clear` ведёт себя как раньше: чистит файл, экранную историю и стек агента.
- `/logictask` по-прежнему не попадает в стек и в историю — без изменений.
- Наблюдаемое поведение меняется ровно в одном месте: первый вопрос после перезапуска
  с непустой историей отправляется вместе с восстановленными обменами; «prompt_tokens»
  в строке usage растёт соответственно. Первый запуск с пустой историей не меняется.

## Capabilities

### Modified Capabilities

- `history-persistence`: требование «Реплей истории не является контекстом модели»
  заменяется на обратное — реплей при старте засеивает стек сообщений агента.
- `agent`: добавлено требование восстановления стека из сохранённой истории
  (владение стеком, кап и пересборка system не меняются).

## Impact

- Код: `core/tabletop_agent.py` (новый метод `restore_context`), `ui/tui_app.py`
  (вызов засева после реплея).
- Тесты: юнит-тесты агента (засев, кап, пересборка user-хода, `/clear` после засева);
  e2e-тест контекста переворачивается — первый вопрос после рестарта уходит в API
  вместе с прошлым обменом.
- Документация: `README.md`, `CLAUDE.md` (раздел про session-only контекст агента).
