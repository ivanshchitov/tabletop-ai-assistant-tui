## MODIFIED Requirements

### Requirement: Изоляция окружения тестов
Тесты SHALL изолировать внешние эффекты: история — во временном файле (переопределение пути), долговременная
память — во временном файле (переопределение пути), профили пользователя — во временном файле (переопределение
пути), состояние задачи — во временном файле (переопределение пути), планировщик заданий — во временном файле
(переопределение пути), результаты задач — во временном
каталоге (переопределение пути), эндпоинт — на локальном stub-сервере
(переопределение адреса), анимация печати — свёрнута
(переопределение паузы), MCP-серверы — на единственном локальном фейковом сервере, заменяющем весь реестр (переопределение
команды запуска и её аргументов), внешний API собственного MCP-сервера проекта — на локальной заглушке
(переопределение базового адреса). Без этих переопределений любой прогон писал бы в единственные реальные файлы состояния
в корне репозитория и стучался в реальный API. Новый файл состояния приложения SHALL получать такое же
переопределение пути, как история: иначе любой прогон — тестовый в том числе — читал бы и писал реальный файл
репозитория.

#### Scenario: Реальная история не трогается
- **WHEN** выполняется любой автоматический прогон тестов
- **THEN** файл `history.json` в корне репозитория не изменяется

#### Scenario: Реальные файлы состояния не трогаются
- **WHEN** выполняется любой автоматический прогон тестов
- **THEN** ни `history.json`, ни `memory.json`, ни `profile.json`, ни `task.json`, ни `schedule.json` в корне репозитория не читаются и не изменяются

#### Scenario: Профили в тестовом прогоне изолированы
- **WHEN** e2e-тест настраивает профиль пользователя в приложении
- **THEN** профиль записан во временный файл прогона, а реальный `profile.json` репозитория не тронут

#### Scenario: Результаты задач в тестовом прогоне изолированы
- **WHEN** e2e-тест проводит задачу до Done
- **THEN** файл результата записан во временный каталог прогона, а `tasks/` репозитория не тронут

#### Scenario: Очередь задач в тестовом прогоне изолирована
- **WHEN** e2e-тест ведёт задачи через конвейер
- **THEN** очередь задач записана во временный файл прогона, а реальный `task.json` репозитория не тронут

#### Scenario: Внешний MCP-сервер в прогоне не поднимается
- **WHEN** выполняется автоматический прогон тестов, проверяющий подключение к MCP
- **THEN** поднимается локальный фейковый сервер прогона, а ни один сервер реестра не запускается и сеть не используется

#### Scenario: Запуск приложения в прогоне не поднимает реестр
- **WHEN** e2e-сценарий запускает приложение, которое при старте подключается к MCP
- **THEN** поднимается только фейковый сервер прогона, и запуск не зависит ни от сети, ни от внешних пакетов

#### Scenario: Внешний API своего сервера в прогоне не вызывается
- **WHEN** выполняется автоматический прогон тестов, проверяющий инструменты собственного MCP-сервера
- **THEN** сервер обращается к локальной заглушке прогона, а публичный внешний API не вызывается

#### Scenario: Планировщик в тестовом прогоне изолирован
- **WHEN** e2e-тест ставит задание планировщика и выполняет его фоновым исполнителем
- **THEN** задания и прогоны записаны во временный файл прогона, а реальный `schedule.json` репозитория не тронут
