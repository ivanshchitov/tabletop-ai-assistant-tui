## Why

Собственный MCP-сервер проекта отвечает только на вызовы «здесь и сейчас»: пользователь спрашивает — сервер
ходит во внешний API правил и отдаёт ответ. Всё, что должно происходить без вопроса — регулярный сбор данных,
отложенное действие, накопление картины за несколько прогонов — сделать нечем, и агент не может ничего
сообщить сам, пока его не спросят. Задача дня 18 челленджа требует именно этого: инструмент с отложенным или
периодическим выполнением, который сохраняет данные, выполняется по расписанию и возвращает агрегированный
результат, и агент, работающий круглосуточно и периодически выдающий сводку.

## What Changes

- Собственный MCP-сервер проекта получает инструмент сбора данных по разделу правил: он возвращает срез
  раздела и одновременно накапливает собранное, различая записи, встреченные впервые, и уже известные.
- Тот же сервер получает инструменты планировщика: постановка задания (какой инструмент этого сервера вызывать,
  с какими аргументами, с каким периодом и через какую задержку первого запуска), перечень заданий, выполнение
  просроченных заданий и агрегированный отчёт по всем заданиям.
- Задания, журнал прогонов и накопленные данные хранятся в отдельном файле состояния приложения (JSON) с
  переопределяемым путём и терпимым чтением, как прочие файлы состояния проекта.
- В корне репозитория появляется фоновый исполнитель расписания: он периодически просит сервер выполнить
  просроченные задания и тем обеспечивает круглосуточную работу; отдельный режим одного прогона позволяет
  проверять его автоматически.
- Агент получает сводку планировщика: он владеет хранилищем заданий, помнит, о каких прогонах уже сообщал, и
  после очередного хода отдаёт снимок новых прогонов, а также полный снимок состояния планировщика.
- Терминал получает команду отчёта планировщика, строку итога при запуске и строку-объявление о новых прогонах
  после ответа; строки экранные и в историю диалога не пишутся.

## Capabilities

### New Capabilities
- `scheduled-jobs`: отложенные и периодические задания собственного MCP-сервера — постановка, хранение,
  выполнение по расписанию, агрегированный результат, фоновый исполнитель и сводка планировщика у агента.

### Modified Capabilities
- `mcp-integration`: собственный сервер проекта объявляет не три инструмента, а набор, дополненный сбором
  данных с накоплением.
- `configuration`: добавляется переменная переопределения пути к файлу планировщика.
- `terminal-ui`: список команд пополняется командой отчёта планировщика; появляются отчёт и строки планировщика.
- `test-infrastructure`: изоляция прогона распространяется на файл планировщика.

## Impact

- `mcp_server/dnd_tools.py`, `mcp_server/dnd_server.py`, новый `mcp_server/scheduler.py` — инструменты сервера.
- `core/schedule_store.py` (новый), `core/config.py` (путь файла и переменная окружения),
  `core/tabletop_agent.py` (хранилище, курсор показанного, снимки).
- `ui/tui_app.py`, `ui/commands_screen.py` — команда, отчёт и строки.
- `tabletop-scheduler.py` (новый) — фоновый исполнитель расписания.
- `tests/unit/` (стор, инструмент сбора, планировщик, агент, сервер как процесс), `tests/e2e/` (команда, строка
  объявления, изоляция), `tests/e2e/harness.py` (проброс переменной), `.gitignore`.
- Внешних зависимостей не добавляется: используются уже подключённые `mcp` и `requests`.
