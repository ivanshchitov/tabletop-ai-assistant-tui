## Context

См. proposal.md. Текущий SQLite хранит текст чанков и хеш-векторы 384 измерений; выбор модели чата уже различает локальные пресеты.

## Goals / Non-Goals

Обеспечить согласованные embedding-векторы при переключении модели и совместимость существующей базы. Облачные embedding-сервисы и новые настройки интерфейса не добавляются.

## Decisions

- Читать embedding-флаг INI отдельно от пресетов чата. При одном embedding-пресете использовать его; при нескольких выдавать понятную ошибку неоднозначной конфигурации вместо случайного выбора.
- Новый модуль обращается к локальному OpenAI-совместимому `/v1/embeddings`, производному от локального URL. Проверять конечные числовые значения, размерность, соответствие входам; нормализовать векторы для cosine.
- Хеш-векторы оставить в существующей таблице; дополнительные векторы хранить по идентификатору embedding-модели и чанка в отдельной таблице того же SQLite. Не заменять базовые векторы: это сохраняет облачный путь и старые базы.
- При первом поиске локальной моделью заполнить отсутствующие векторы сохранённых чанков транзакционно. При `/rules index` локальной моделью подготовить их до атомарной замены базы. Индексация при запуске по-прежнему запрещена.
- Передавать выбранного embedding-провайдера из агента и команд TUI. RAG off и отсутствующий индекс проверять раньше embedding-запросов. Ошибки отражать в отчёте и интерфейсе, без хеш-fallback.

## Risks / Trade-offs

Первый локальный поиск дольше → сохранять векторы для повторного использования.
Сервер недоступен или возвращает некорректные данные → таймаут, понятная ошибка, отсутствие частичной записи.
Смена файла весов под прежним именем → пользователь пересоздаёт индекс через `/rules index`.

## Migration Plan

Старый индекс читается без изменений; дополнительная таблица создаётся при первом использовании локальных embeddings. Откат сохраняет возможность чтения исходных хеш-векторов. Правки пользователя в models.ini сохраняются.
