## MODIFIED Requirements

### Requirement: Собственный MCP-сервер проекта над внешним API
Проект SHALL включать собственный MCP-сервер, работающий по транспорту stdio и получающий данные из внешнего публичного API правил настольной ролевой игры. Сервер SHALL объявлять обобщённые инструменты, покрывающие все разделы этого API: перечень доступных разделов, поиск записей внутри раздела, получение полной записи раздела по её идентификатору и сбор данных по разделу с накоплением собранного между вызовами, а также инструменты обработки и сохранения: сводку результата поиска и сохранение текста в файл каталога выгрузок. Сверх справочных инструментов сервер SHALL объявлять инструменты планировщика, позволяющие вызывать его собственные инструменты по расписанию. Перечень разделов SHALL браться у самого API, а не задаваться списком в коде сервера. Адрес внешнего API SHALL переопределяться переменной окружения, чтобы автоматический прогон обращался к локальной заглушке и не выходил в сеть. Отказ внешнего API (недоступность, таймаут, неизвестная запись) SHALL возвращаться вызывающей стороне текстом результата с описанием причины и SHALL NOT завершать серверный процесс. Любой неудачный вызов инструмента собственного сервера (отказ внешнего API, неверные аргументы, неизвестный инструмент) SHALL помечаться протокольным признаком ошибки результата, чтобы клиент отличал отказ от данных.

#### Scenario: Сервер объявляет свои инструменты
- **WHEN** клиент подключается к собственному серверу проекта и запрашивает список инструментов
- **THEN** сервер отдаёт справочные инструменты с именами и описаниями: перечень разделов, поиск по разделу, запись по идентификатору и сбор данных по разделу

#### Scenario: Сервер объявляет инструменты планировщика
- **WHEN** клиент запрашивает список инструментов собственного сервера проекта
- **THEN** среди них есть инструменты постановки задания, перечня заданий, выполнения просроченных заданий и агрегированного отчёта

#### Scenario: Разделы приходят от внешнего API
- **WHEN** вызван инструмент перечня разделов
- **THEN** ответ содержит разделы, перечисленные самим внешним API

#### Scenario: Запись раздела возвращается по идентификатору
- **WHEN** вызван инструмент записи с известным разделом и известным идентификатором
- **THEN** ответ содержит поля записи, как их отдал внешний API

#### Scenario: Поиск по разделу ограничен лимитом
- **WHEN** вызван инструмент поиска с запросом и лимитом записей
- **THEN** ответ содержит не больше указанного числа найденных записей

#### Scenario: Внешний API недоступен
- **WHEN** внешний API не отвечает или возвращает ошибку
- **THEN** результат вызова несёт текст о причине сбоя, а серверный процесс продолжает работать

#### Scenario: Адрес внешнего API переопределён
- **WHEN** задана переменная окружения с адресом внешнего API
- **THEN** сервер обращается по указанному адресу, а адрес по умолчанию не используется

#### Scenario: Сервер объявляет инструменты обработки и сохранения
- **WHEN** клиент запрашивает список инструментов собственного сервера проекта
- **THEN** среди них есть инструмент сводки и инструмент сохранения в файл

#### Scenario: Отказ помечен признаком ошибки
- **WHEN** инструмент собственного сервера вызван с неверными аргументами
- **THEN** результат вызова несёт текст причины и протокольный признак ошибки, а клиент получает сбой вызова, а не данные

### Requirement: Автоматический выбор инструмента перед вопросом
При включённом автоматическом режиме агент SHALL перед отправкой вопроса выполнять отдельный запрос к модели, в котором перечислены доступные инструменты с их описаниями и входными параметрами, и SHALL разбирать ответ модели на стороне приложения, без опоры на формат ответа, навязанный API. Ответ выбора SHALL называть один инструмент или цепочку шагов; выбранные инструменты SHALL вызываться с выбранными аргументами по порядку. Ответ модели, означающий «инструмент не нужен», SHALL быть допустимым исходом и SHALL NOT считаться сбоем. Сбой выбора (ошибка запроса, пустой или неразбираемый ответ, неизвестное имя инструмента) и сбой самого вызова SHALL NOT блокировать ответ на вопрос: вопрос SHALL уходить без результата инструмента. Расход вспомогательного запроса SHALL попадать в счётчики сессии. При выключенном автоматическом режиме вспомогательный запрос SHALL NOT отправляться вовсе. Начальное состояние режима SHALL браться из конфигурации приложения, а переключение в течение сессии SHALL действовать до её конца.

#### Scenario: Модель выбирает инструмент
- **WHEN** пользователь задаёт вопрос, для которого модель выбирает инструмент и аргументы
- **THEN** инструмент вызывается с этими аргументами до отправки вопроса

#### Scenario: Инструмент не нужен
- **WHEN** модель отвечает, что подходящего инструмента нет
- **THEN** вопрос уходит без вызова инструмента и без сообщения об ошибке

#### Scenario: Выбор не удался
- **WHEN** запрос выбора завершается ошибкой или ответ невозможно разобрать
- **THEN** пользователь получает ответ на свой вопрос, а сведения о неудавшемся выборе доступны вызывающей стороне

#### Scenario: Вызов выбранного инструмента не удался
- **WHEN** выбранный инструмент возвращает ошибку или сервер недоступен
- **THEN** пользователь получает ответ на свой вопрос, а сведения о неудавшемся вызове доступны вызывающей стороне

#### Scenario: Автоматический режим выключен
- **WHEN** автоматический режим выключен и пользователь задаёт вопрос
- **THEN** вспомогательный запрос выбора не отправляется и ни один инструмент не вызывается

#### Scenario: Расход вспомогательного запроса учтён
- **WHEN** выполнен запрос выбора инструмента
- **THEN** его токены и стоимость попадают в счётчики сессии

#### Scenario: Модель выбирает цепочку
- **WHEN** модель в ответ на запрос выбора возвращает цепочку шагов
- **THEN** шаги выполняются по порядку до отправки вопроса без дополнительных запросов выбора

### Requirement: Результат инструмента в запросе к модели
Успешный результат вызова инструмента SHALL уходить в запрос к модели отдельным системным сообщением, расположенным выше сообщений диалога, вместе с указанием, что это данные внешнего источника, полученные для текущего вопроса. При цепочке шагов SHALL уходить результат каждого успешно выполненного шага с его номером, именем инструмента и аргументами, где аргумент, полученный по ссылке, SHALL называться ссылкой на шаг, а не повторять переданный текст. Результат SHALL NOT записываться в файл истории диалога и SHALL NOT восстанавливаться при следующем запуске. Когда инструмент не вызывался или вызов не удался, состав сообщений запроса SHALL оставаться прежним.

#### Scenario: Результат попадает в запрос
- **WHEN** инструмент вызван успешно перед вопросом
- **THEN** запрос к модели содержит отдельное системное сообщение с результатом инструмента выше сообщений диалога

#### Scenario: Без вызова состав сообщений прежний
- **WHEN** инструмент не вызывался или вызов не удался
- **THEN** запрос к модели не содержит сообщения с результатом инструмента

#### Scenario: Результат не попадает в историю
- **WHEN** обмен с вызовом инструмента завершён
- **THEN** в файле истории сохранены только вопрос и ответ, без результата инструмента

#### Scenario: Результаты всех шагов цепочки в запросе
- **WHEN** перед вопросом выполнена цепочка из трёх шагов
- **THEN** системное сообщение с результатами называет все три шага, а текст, переданный по ссылке, в аргументах не повторяется
