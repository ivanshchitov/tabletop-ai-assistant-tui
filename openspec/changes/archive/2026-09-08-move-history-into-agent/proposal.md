## Why

Неделя 2 челленджа — управление памятью агента. Сейчас у агента две памяти разнесены по
разным владельцам: стек сессии (`_turns`) живёт в `TabletopAgent`, а долговременная память
(`HistoryManager`, `history.json`) — в `TabletopAITUI`, который вручную передаёт пары
«вопрос–ответ» в `restore_context()` при старте и пишет `history.add()` после каждого
обмена. Владение памятью — обязанность агента (стадия MEMORY из недельной модели), а
интерфейс должен только показывать. Поведение пользователя не меняется ни в чём — это
перенос владения внутри `core/`.

## What Changes

- `TabletopAgent` принимает `HistoryManager` в конструкторе (по умолчанию — менеджер с
  дефолтным путём; тесты подставляют файл во временном каталоге) и становится единственным
  владельцем обеих памятей: стека сообщений сессии и файла `history.json`.
- **Автовосстановление при конструировании**: агент сам засеивает стек из собственной
  истории (`restore_context()` без параметров) — «забыть вызвать» невозможно.
- **Запись внутри `ask()`**: успешный обмен сразу попадает в `self.history.add(question,
  answer)` — немедленное сохранение на диск остаётся, но выполняет его агент.
- **`reset()` чистит обе памяти**: стек и файл (команда `/clear`).
- `TabletopAITUI` отдаёт владение историей: сигнатура `TabletopAITUI(console=, history=,
  client=)` сохраняется, но менеджер пробрасывается в конструктор агента; реплей при
  старте печатает `agent.history.dialogues`; `/clear` — только `agent.reset()` и сообщение;
  `history.save()` при выходе не нужен (немедленная запись уже в менеджере).
- Формат `history.json`, путь, `TABLETOP_HISTORY_FILE`, кап 50 — без изменений.

## Capabilities

### Modified Capabilities

- `agent`: добавлено требование владения долговременной памятью — запись после успешного
  обмена, автовосстановление при создании, очистка обеих памятей одним `reset()`.

Capability `history-persistence` не меняется: её требования описывают файл и поведение,
а не владельца, и остаются истинными дословно.

## Impact

- Код: `core/tabletop_agent.py` (параметр `history`, запись в `ask()`, автовосстановление,
  `reset()` чистит обе памяти), `ui/tui_app.py` (проброс, реплей из памяти агента, `/clear`
  без прямых вызовов истории, без `save()` на выходе).
- Тесты: юнит-тесты агента получают инъекцию `HistoryManager` во временном файле; новые
  ассерты: `ask()` пишет на диск сразу, стек восстанавливается из собственного файла,
  `reset()` чистит обе памяти; юнит-тесты TUI — реплей и `/clear` через агента; e2e должны
  остаться зелёными без правок.
- Документация: `README.md`, `CLAUDE.md` (владение памятью — в агенте).
