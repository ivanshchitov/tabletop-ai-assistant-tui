## Context

Владение памятью агента сейчас разделено: `TabletopAgent` держит стек сессии, а
`HistoryManager` держит `TabletopAITUI` — он же вызывает `history.add()` после ответа,
`history.clear()` на `/clear`, `history.save()` на выходе и передаёт пары в
`restore_context(dialogues)` при старте. Недельная модель агента (PERCEPTION, MEMORY, …)
относит память к агенту; интерфейс — только показ. Перенос владения не меняет ни сценария
пользователя, ни формат файла, ни какие-либо ассерты e2e-слоя.

Ограничения, которые нельзя сломать:

- Сигнатура `TabletopAITUI(console=, history=, client=)` сохраняется (зафиксирована
  спекой дня 6): параметр пробрасывается в конструктор агента.
- Формат `history.json`, путь через `TABLETOP_HISTORY_FILE`, кап 50, немедленная запись,
  битый файл → пустая история — без изменений.
- Никакой повторной записи: `HistoryManager.add()` уже пишет на диск сразу; `save()` на
  выходе становится лишним и убирается.
- Юнит-тесты агента обязаны получать файл во временном каталоге: с автовосстановлением
  агент, созданный с дефолтным менеджером, прочитает реальный `history.json` пользователя.

## Goals / Non-Goals

Goals:

- Обе памяти агента (стек сессии + файл истории) — в одном владельце: `TabletopAgent`.
- Восстановление при создании агента — автоматическое и единственное (без вызова снаружи).
- Уменьшение поверхности `TabletopAITUI`: никаких прямых вызовов истории, кроме реплея.

Non-Goals:

- Смена формата хранилища (JSON → SQLite), хранение сырых промптов, несколько профилей.
- Изменение наблюдаемого поведения приложения (реплей, `/clear`, статус-бар — как раньше).

## Decisions

### Автовосстановление в конструкторе агента

`TabletopAgent.__init__` вызывает `restore_context()` (без параметров — из собственной
истории) в самом конце инициализации. Альтернатива — явный вызов из `run()` — оставляет
окно «забыли вызвать» и сохраняет у интерфейса роль, которой у него быть не должно.
Следствие для тестов: `make_agent()` подставляет `HistoryManager(tmp-файл)` всегда —
и детерминизм, и защита реального файла пользователя.

### Запись в `ask()`, а не в `_remember()`

`_remember()` — внутренняя работа со стеком; запись в файл — побочный эффект успешного
обмена целиком. Пишем в `ask()` после `self._last_result = meta`, рядом с `_remember`:
одна точка «обмен удался», в `_remember` стековая механика не смешивается с диском.
Прогоны `/logictask` по-прежнему историю не трогают (требование спеки сохраняется).

### `reset()` — единственная точка очистки

`/clear` в UI: напечатать подтверждение и вызвать `agent.reset()`. Прямые вызовы
`history.clear()` из UI исчезают — инвариант «стек и файл пустеют вместе» теперь
структурный, а не дисциплина вызовов.

## Risks / Trade-offs

- Дефолтный конструктор `TabletopAgent(client)` без истории теперь читает реальный
  `history.json` — приёмлемо для продакшена; тесты всегда инъектируют tmp-файл
  (проверено ревизией всех мест создания агента: TUI и `make_agent`).
- Двойное представление (стек ходов + пары в файле) остаётся; согласованность структурная:
  обе памяти пишутся в одних точках (`ask`, `reset`), тест на инвариант «стек
  восстанавливается из файла» фиксирует соответствие.
