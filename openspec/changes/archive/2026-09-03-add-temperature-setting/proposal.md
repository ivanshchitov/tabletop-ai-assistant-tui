## Why

Задание дня 4 челленджа требует выполнять один и тот же запрос при разных значениях temperature (0 / 0.7 / 1.2) и сравнивать ответы. Сейчас температура зашита в коде константой (`config.TEMPERATURE = 0.7`) и недоступна пользователю. Регулируемая настройка температуры решает задание и полезна сама по себе: температура — главный рычаг баланса «точность ↔ креативность».

## What Changes

- Новая четвёртая настройка ответа — `temperature` (температура запроса к модели).
- Диапазон 0.0..2.0, по умолчанию 0.7 (прежняя константа становится значением по умолчанию).
- Значение задаётся десятичным числом **не более чем с одним знаком после точки**. Ограничение реализуется на вводе: поле температуры физически не позволяет набрать второй знак после точки (лишняя цифра игнорируется), поэтому ошибка формата через экран недостижима. Ядро сохраняет проверку как инвариант (`with_temperature` отклоняет более одного знака — защита от программных вызовов), диапазон и нечисловое — ошибка валидации без тихого клампинга, как у остальных настроек.
- На экране `/settings` появляется четвёртая строка «Температура»: ввод цифр и одной десятичной точки, Backspace, валидация при выходе (Esc), независимое применение полей сохраняется.
- Клиент API принимает температуру параметром; в payload уходит значение из настроек сессии вместо константы. `/logictask` остаётся на значении по умолчанию (настройки формата/объёма/температуры на него не влияют — уже зафиксированное решение).
- Статус-бар после обмена и смены настроек показывает текущую температуру.
- Конфиг: `MIN_TEMPERATURE = 0.0`, `MAX_TEMPERATURE = 2.0`; дефолт — существующая константа.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `answer-settings`: три настройки становятся четырьмя — добавляется температура с диапазоном 0.0..2.0, значением по умолчанию 0.7 и правилом «максимум один знак после точки» как инвариантом снимка (проверяется ядром, включая программные вызовы).
- `settings-screen`: экран SHALL показывать четыре поля; на строке температуры цифры и одна точка дописываются в поле, но не более одной цифры после точки — второй знак ввести невозможно; повторная точка и прочие нечисловые клавиши игнорируются; навигация циклически по четырём строкам.
- `api-integration`: температура в теле запроса SHALL браться из настройки сессии (по умолчанию 0.7), а не из фиксированной константы; для `/logictask` температура SHALL оставаться равной значению по умолчанию.
- `configuration`: список фиксированных констант дополняется диапазоном и значением по умолчанию температуры.
- `terminal-ui`: статус-бар SHALL дополнительно показывать текущую температуру.

## Impact

- `core/config.py` — константы диапазона температуры.
- `core/answer_settings.py` — поле `temperature`, `with_temperature()` с валидацией диапазона и одного знака после точки.
- `ui/settings_screen.py` — четвёртая строка редьюсера, ввод цифр и одной точки, парсинг/валидация при выходе.
- `ui/tui_app.py` — отрисовка строки и статуса, передача температуры в клиент.
- `core/api_client.py` — параметр `temperature` у `ask()`.
- Тесты: `tests/unit/test_answer_settings.py`, `tests/unit/test_settings_screen.py`, `tests/unit/test_tui_app.py`, `tests/unit/test_api_client.py`, `tests/e2e/test_settings_screen.py`, `tests/e2e/test_api_payload.py` (фактические файлы уточняются на этапе tasks).
