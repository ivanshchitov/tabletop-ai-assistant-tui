## Context

См. proposal.md — Why. Сейчас температура — константа `config.TEMPERATURE = 0.7`, зашитая в payload в `core/api_client.py`. Настройки сессии — неизменяемый dataclass `AnswerSettings` (формат, объём, лимит списка) с паттерном `with_*` → новый снимок, ошибки — `AnswerSettingsError` без клампинга. Экран `/settings` — чистый редьюсер `ui/settings_screen.py` (`initial_state` → `apply_key` → `apply_to_settings`), числовые поля хранятся строками до выхода с экрана.

## Goals / Non-Goals

**Goals:**
- Температура управляется пользователем через `/settings` и доходит до API в каждом запросе.
- Формат ввода строго ограничен: десятичное число, максимум один знак после точки.
- Поведение по умолчанию не меняется (0.7), `/logictask` остаётся на дефолтной температуре.

**Non-Goals:**
- Сохранение настроек между сессиями (AnswerSettings остаётся session-only по главному спеку).
- Проверка диапазона на стороне API-ответа; диапазон валидируется только клиентски.
- Смена температуры для `/logictask`.

## Decisions

1. **Диапазон 0.0..2.0** — стандарт OpenAI-совместимых API; 0 и 1.2 из задания внутри диапазона. Альтернатива 0..1 отброшена: задание требует 1.2.
2. **Правило «один знак после точки» — на вводе, инвариант — в ядре.** Пользователь не может ввести второй знак: редьюсер допускает цифру после точки, только если её там ещё нет; значение с двумя знаками через экран недостижимо, ошибки формата у пользователя не возникает. Ядро (`with_temperature`) сохраняет проверку `round(value, 1) != value` → `AnswerSettingsError` как инвариант для программных вызовов. Округление отброшено: противоречит принципу «без тихого клампинга» (0.55 молча превратился бы в 0.6). Сравнение через `round` надёжно против двоичного представления float: значение, уже имеющее один знак (например, 0.7), при `round(0.7, 1)` даёт тот же float.
3. **Ввод на экране: цифры + одна точка + не более одной цифры после точки.** Точка допускается, только если её ещё нет в поле; цифра после точки — только если после точки ещё нет цифры. Парсинг на выходе — регэксп `^\d+(\.\d)?$`: отбрасывает пустое и хвостовую точку («0.» — ошибка про температуру). Минус не принимается — диапазон неотрицательный.
4. **`ask(..., temperature: float = config.TEMPERATURE)`** — температура становится параметром клиента с дефолтом из константы; `ui/tui_app.py` передаёт `self.settings.temperature`. Так `/logictask`, вызывающий `ask()` без температуры, автоматически остаётся на дефолте без отдельного кода.
5. **Четвёртая строка панели после лимита списка** (`ROW_TEMPERATURE = 3`); цикл навигации естественным образом расширяется через `ROWS_COUNT`.

## Risks / Trade-offs

- [Float-сравнение при валидации одного знака] → проверка только через `round(value, 1) == value`, без сравнения строк; покрыть unit-тестами 0.7/1.2/0.55/2.0.
- [Промежуточное «0.» при наборе] → валидируется только на выходе (как у других полей); если пользователь выйдет с «0.», увидит ошибку и прежнее значение.
- [Расширение тестирующих хелперов e2e] → фактические имена файлов тестов фиксируются в tasks.md на этапе apply.

## Migration Plan

Обычная ветка → TDD → merge в `main`. Обратная совместимость: дефолт не меняется, история и `.env` не затрагиваются. Откат — revert мержа.
