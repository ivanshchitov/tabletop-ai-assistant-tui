## Context

См. proposal.md для мотивации. `APIClient` уже маршрутизирует модели из INI в локальный сервер и объединяет системные блоки. `TabletopAgent._build_messages` собирает инструкции, `_ask_question` задаёт параметры основного ответа и повторов. Вспомогательные запросы имеют собственные методы. В кэше подтверждены обе 2B-квантования: Q4_K_M и Q4_K_XL. Общий серверный контекст сейчас 32000; минимальный лимит генерации приложения — 2000. Исторические ответы дня 26 не заменяют новый исходный замер.

## Goals / Non-Goals

**Goals:** управляемая оптимизация коротких ответов, сохранение исходного режима, отдельное сравнение настроек и квантования, честная оценка качества.

**Non-Goals:** обучение весов, изменение облачного поведения, перестройка RAG или памяти, оптимизация всех вспомогательных этапов агента, универсальная панель произвольных параметров генерации.

## Decisions

1. **Профиль определяется выбранным пресетом.** Добавить исходный Q4_K_XL и два именованных оптимизированных пресета с `hf-repo`, указывающим на уже установленные веса. Для оптимизированных пресетов `c=8192`, reasoning=auto и бюджет 256; исходные — 32000 и те же параметры рассуждения. Использовать поддержку именованных INI-пресетов llama.cpp; подтвердить совместимость с установленным бинарником при сухом прогоне. Отдельные пресеты позволяют серверу действительно выделять меньший контекст. Простое уменьшение `max_session_tokens` этого не доказывает. Облачные и embedding-пресеты сохраняются.

2. **Компактная политика в `core/local_llm.py`.** Неизменяемые описания профилей, соответствие модель ↔ квантование ↔ режим, вычисление фактических параметров основного ответа. Оптимизированный режим имеет фиксированные temperature/max_tokens; исходный читает прежние настройки сессии. `/local` явно объясняет приоритет. `/local baseline|optimized` переключает пресет через агента; неподдерживаемая модель или неверный ввод не меняют состояние. Выбор через `/models` эквивалентен переключению командой. Профиль не сохраняется новым файлом.

3. **Основной ответ меняется на ответственном уровне.** В `_build_messages` подменить только базовый системный шаблон при оптимизированном пресете; инструкции формата и остальные блоки сохранить. В `_ask_question` использовать фактические параметры профиля, включая повторы инвариантов и цитат. Вспомогательные запросы сохраняют свой протокол. Не подменять все запросы в HTTP-клиенте: это нарушило бы генерацию JSON для поиска и инструментов.

4. **Короткий предметный шаблон.** `assets/local_system_prompt.md` содержит роль настольного помощника, прямой ответ, арифметику по шагам, уточнение редакции, признание неизвестного и существующий отказ для посторонних тем. Не включать готовые ответы контрольного набора: промпт должен работать на вопросах, которых в нём нет.

5. **Измерения отдельным сценарием.** `scripts/benchmark_local_llm.py` работает с настоящим агентом и API в отдельном временном каталоге состояния, отключает RAG и инструменты. Контрольные вопросы: три вопроса (конь, стоимость CATAN, вероятности). Дополнительные вопросы доступны только при явном выборе через CLI и не входят в сокращённое сравнение. Эталонные смысловые критерии задаются до получения ответов. Один одинаковый seed=42 для всех вариантов (9 запросов): после уточнения пользователя цель — демонстрационное сравнение, без поиска предельной точности и оценки стабильности на нескольких seed; каждый вопрос начинает новый диалог. Прогрев на отдельном вопросе не попадает в статистику; порядок вариантов и версия бинарника записываются. Сохранить JSON с полными ответами и параметрами, агрегированный Markdown; смысловая оценка отдельно проверяется человеком/агентом по тексту, а не только поиском слов.

6. **Ресурсы с определённым смыслом.** Для измерений запускать отдельный управляемый сервер на свободном порту; не останавливать пользовательский сервер. Снимать RSS родителя и дочерних процессов с коротким интервалом, сохранять пик, длительность загрузки и размеры фактических GGUF. Это выборочный пик резидентной памяти процессов, не полное потребление видеопамяти или энергии; это ограничение указывается в отчёте. Если `ps` запрещён песочницей, запросить штатное разрешение для замера вместо выдумывания числа. Остановить только собственную группу процессов в finally; запретить непреднамеренную загрузку весов из сети.

7. **Проверки и коммиты.** Проверить политику профилей, форматы и повторы, отсутствие изменения облачных/вспомогательных запросов, команду и маршрутизацию обоих квантований, корректность отчёта измерений и очистку процессов. Один логически связанный коммит реализации после показа diff и подтверждения; архив и документация также по принятому циклу проекта.

## Risks / Trade-offs

- Небольшая модель сохраняет ошибки → проверять ответы по смыслу; выбрать лучший измеренный профиль и явно указать оставшиеся ошибки.
- 1024 токена недостаточно для рассуждения → фиксировать finish_reason и пустой content; при необходимости изменить кандидат и согласованные артефакты по фактическому результату.
- 8192 ограничивает длинные беседы → документировать назначение коротких ответов; исходный пресет остаётся доступен.
- Новый предметный промпт конкурирует с форматом → сохранить инструкции формата и инварианты отдельными блоками, проверить JSON/compact.
- Серверное кэширование и загрузка искажают скорость → отделить прогрев/загрузку от запросов, одинаковые вопросы и seed, отключить повторное использование prompt cache при измерении, фиксировать порядок.
- Фоновая нагрузка и разделяемая память искажают RSS → замеры одного варианта за раз, описание метода и ограничений, без утверждений о полной памяти устройства.

## Migration Plan

Добавить пресеты и перезапустить управляемый сервер перед первым использованием. Исходные имена моделей сохраняются. Откат — выбрать `/local baseline` или исходный пресет; пользовательская история и настройки не мигрируют. Удаление нового кода не требует изменения файлов состояния.
