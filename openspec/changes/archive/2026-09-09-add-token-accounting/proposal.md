## Why

День 8 челленджа требует подсчёта токенов агента: для текущего запроса, для всей истории диалога
и для ответа модели — и наглядного сравнения короткого диалога, длинного диалога и диалога,
превышающего лимит модели (рост стоимости/токенов и то, что ломается при переполнении). Сейчас в
проекте есть только метрики последнего запроса (`AnswerMeta` + строка после ответа): накопительной
статистики сессии нет, размер контекстного окна пользователь не видит, а случай «модель исчерпала
бюджет `max_tokens` и вернула пустой `content`» (задокументированное поведение reasoning-моделей)
проходит для пользователя бесследно — просто нет ответа.

## What Changes

- Новый накопитель `SessionLedger` в `core/usage.py`: после каждого успешного запроса агент
  записывает в него метрики (`prompt_tokens`, `completion_tokens`, `total_tokens`, стоимость).
  Накопитель отдаёт: число запросов, суммарные входные/выходные/общие токены, суммарную
  стоимость (None, если стоимость хоть одного запроса неизвестна) и средний размер запроса.
- Приближённая клиентская оценка токенов `estimate_tokens(text)` в `core/usage.py` (константа
  `ESTIMATED_CHARS_PER_TOKEN` в `core/config.py`) — позволяет показать объём истории диалога в
  токенах без обращения к API.
- `TabletopAgent` (`core/tabletop_agent.py`) владеет накопителем: записывает метрику каждого
  успешного запроса (вопрос и каждый запрос `/logictask`), сбрасывает её в `reset()` (вместе с
  очисткой контекста) и отдаёт снимок сессии (`session_usage`) и оценку токенов стека сообщений
  (системное сообщение + ходы сессии).
- `APIClient` (`core/api_client.py`) добавляет в `AnswerMeta` поле `finish_reason` (значение
  `finish_reason` первого выбора из ответа API; None, если поля нет). Остальные поля и поведение
  не меняются.
- Предупреждение об усечении в `ui/tui_app.py`: если ответ пуст, а `finish_reason == "length"` —
  печатается предупреждение, что модель исчерпала бюджет `max_tokens` (случай reasoning-моделей);
  если ответ непуст, но `finish_reason == "length"` — предупреждение, что ответ мог быть обрезан.
  Для пути вопроса; `/logictask` не затрагивается (его `max_tokens` закреплён на значении по
  умолчанию).
- Переменная окружения `TABLETOP_HISTORY_LIMIT` (`core/config.py`) переопределяет
  `HISTORY_LIMIT` (по умолчанию 50, как раньше) — единый лимит и для окна сессии, и для файла
  истории. Нужна, чтобы в демо и e2e показать вытеснение старых ходов за секунды, а не за 50+
  обменов.
- Расход в записях истории (`core/history_manager.py`): каждый обмен сохраняется в
  `history.json` с собственными метриками использования — `{"question", "answer", "usage":
  {"prompt_tokens", "completion_tokens", "total_tokens", "cost_usd"}}`. Записи старого формата
  (без `usage`) читаются как обычно, без метрик. Итог «всего диалога» — сумма метрик по записям
  файла; из-за потолка `HISTORY_LIMIT` это расход удержанной истории (вытесненные записи уносят
  свой расход с собой).
- Новая команда `/usage` (`ui/commands_screen.COMMAND_OPTIONS` + обработка в `ui/tui_app.py`):
  печатает отчёт без обращения к модели — последний запрос (токены/стоимость), итоги сессии
  (запросы, входные/выходные/общие токены, стоимость), расход всей сохранённой истории (сумма
  по записям файла), состояние окна контекста (N обменов из лимита + приближённая оценка
  токенов стека). Команда добавляется в автодополнение и панель `/commands` автоматически через
  общий источник `COMMAND_OPTIONS`.
- Статус-бар после каждого шага (`ui/tui_app.py::_print_status_bar`) дополняется итогами
  сессии: суммарные токены и суммарная стоимость всех запросов текущей сессии — рост расхода
  виден после каждого обмена, а не только по явной команде.
- Тестовый stub-сервер (`tests/e2e/stub_api.py`) дополняет ответ полем `finish_reason`, чтобы e2e
  могли проверить предупреждение об усечении.

## Capabilities

### New Capabilities

_(нет — расширяются существующие возможности)_

### Modified Capabilities

- `api-integration`: метрики запроса дополняются причиной завершения генерации
  (`finish_reason`) — без изменения существующего контракта.
- `question-answering`: доп.-информация после ответа дополняется предупреждением об усечении,
  когда модель упёрлась в бюджет `max_tokens`.
- `terminal-ui`: новая команда `/usage` — текстовый отчёт по токенам сессии, расходу
  сохранённой истории и состоянию окна контекста без запросов к модели; статус-бар после
  каждого шага дополняется суммарными токенами и стоимостью сессии.
- `configuration`: список переменных переопределения пополняется `TABLETOP_HISTORY_LIMIT`.
- `history-persistence`: лимит истории читается из конфигурации (по умолчанию 50, прежнее
  поведение) и переопределяется переменной окружения; каждая запись хранит метрики
  использования своего обмена, записи старого формата читаются без них.

## Impact

- Код: `core/usage.py`, `core/config.py`, `core/api_client.py`, `core/tabletop_agent.py`,
  `core/history_manager.py`, `ui/tui_app.py`, `ui/commands_screen.py`.
- Тесты: `tests/unit/test_usage.py`, `tests/unit/test_tabletop_agent.py`, `tests/unit/test_config.py`,
  `tests/unit/test_history_manager.py`, `tests/unit/test_tui_app.py`,
  `tests/unit/test_commands_screen.py`, `tests/e2e/stub_api.py`, `tests/e2e/test_commands_flow.py`;
  возможна правка снапшотов `tests/e2e/snapshots/`.
- Внешние системы: не затрагивает — `finish_reason` — стандартное поле OpenAI-совместимого ответа;
  оценка токенов истории — клиентская эвристика, новых вызовов API не добавляет. Файл
  `history.json` расширяется обратно-совместимо: старые файлы и записи без `usage` читаются как
  раньше.
