## Purpose

Отдельная сущность «агент» — единственное место, где решается, что и как отправляется в LLM: агент владеет стеком сообщений сессии, пересылает его модели целиком и решает фиксированную логическую задачу выбранной стратегией промптинга. Терминальный интерфейс только показывает результат.

## ADDED Requirements

### Requirement: Стек сообщений сессии
Агент SHALL хранить стек сообщений текущей сессии: ход `user` (вопрос) и ход `assistant` (ответ) каждого успешного обмена. Каждый вопрос SHALL отправляться модели вместе со всем стеком, а не одиночным сообщением. Стек SHALL содержать не более `HISTORY_LIMIT` (50) последних обменов: ходы старше этой границы SHALL NOT включаться в запрос. Промежуточные материалы прогонов `/logictask` в стеке не хранятся.

#### Scenario: Второй вопрос несёт контекст
- **WHEN** пользователь задаёт второй вопрос за сессию после успешного ответа на первый
- **THEN** запрос содержит system, первый обмен (user и assistant) и новый user-ход

#### Scenario: Кап на глубину контекста
- **WHEN** в сессии было больше `HISTORY_LIMIT` успешных обменов и задан новый вопрос
- **THEN** запрос содержит system и только последние `HISTORY_LIMIT` обменов, без самых старых

### Requirement: Пересборка системного сообщения
Системное сообщение SHALL NOT храниться в стеке: агент SHALL собирать его из активных настроек ответа (формат, инструкции формата) при каждом запросе. Смена формата или других настроек через `/settings` SHALL действовать на следующий же вопрос. Ходы `user` прошлых обменов SHALL сохранять инструкции объёма и лимита списка на момент того вопроса и не переписываться задним числом.

#### Scenario: Смена формата действует сразу
- **WHEN** пользователь переключил формат на JSON через `/settings` и задал вопрос
- **THEN** системное сообщение этого запроса собрано с JSON-инструкцией

#### Scenario: Прошлые ходы не переписываются
- **WHEN** после двух вопросов с лимитом 200 слов пользователь поднял объём до 500 и задал третий вопрос
- **THEN** user-ходы первых двух вопросов в стеке содержат инструкцию 200 слов, новый ход — 500 слов

### Requirement: Ошибки API отдаются вызывающей стороне
Агент SHALL NOT выводить ничего на экран: при ошибке API (включая исчерпание повторов) агент SHALL передать ошибку вызывающей стороне как исключение. Отображение ошибки и продолжение сессии — обязанность терминального интерфейса.

#### Scenario: Ошибка доходит до интерфейса
- **WHEN** запрос к API завершился ошибкой после всех повторов
- **THEN** агент не печатает ничего сам и отдаёт ошибку исключением вызывающей стороне

### Requirement: Решение логической задачи
Агент SHALL решать фиксированную логическую задачу (волк/коза/капуста) по номеру выбранной стратегии: 1 — прямой запрос, 2 — пошаговое решение, 3 — составление промпта моделью с последующим решением (два запроса), 4 — панель из трёх экспертов (три запроса). Параметры прогонов: модель сессии, без температуры (клиентское значение по умолчанию), `max_tokens` от объёма по умолчанию — настройки ответа сессии к прогонам не применяются. Результаты SHALL отдаваться вызывающей стороне по мере выполнения — по одному на каждый запрос, с меткой роли/этапа. Вызовы прогонов SHALL NOT изменять стек сообщений сессии.

#### Scenario: Состав стратегии 3
- **WHEN** выбрана стратегия 3 (промпт от модели)
- **THEN** выполняется ровно два запроса: составление промпта и решение по нему, оба выданы вызывающей стороне по мере выполнения

#### Scenario: Панель экспертов
- **WHEN** выбрана стратегия 4
- **THEN** выполнено ровно три запроса — по одному на каждого эксперта (шеф, зоопсихолог, теоретик игр), в фиксированном порядке

#### Scenario: Прогон не меняет контекст
- **WHEN** выполнен любой прогон логической задачи
- **THEN** стек сообщений агента после прогона идентичен стеку до него

### Requirement: Сброс контекста
При очистке диалога командой `/clear` агент SHALL опустошать стек сообщений: следующий после очистки вопрос SHALL отправляться без ходов до очистки (system плюс новый user).

#### Scenario: Вопрос после очистки
- **WHEN** после нескольких обменов выполнена команда `/clear` и задан новый вопрос
- **THEN** запрос содержит system и один user-ход, без переписки до очистки
