# Design: add-model-selection

## Context

Модель зашита константой `config.MODEL_NAME`, читаемой в единственном месте — payload в `DeepseekAPIClient.ask()` (`core/api_client.py:61`). Панельные фичи (`/commands`, `/settings`, `/logictask`) уже стандартизованы: чистый редьюсер в `ui/<x>_screen.py` + цикл read-key/redraw в `ui/tui_app.py`. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Сессионный выбор модели из фиксированного списка через панель `/models`.
- Единая точка прохождения модели в payload через параметр `ask()`.
- Нейтральные к имени Deepseek имена классов/исключений/сообщений.

**Non-Goals:**
- Персистентность выбора модели между запусками (как у `AnswerSettings` — бэклог).
- Модель как поле `AnswerSettings`/экрана `/settings` — команда `/models` отдельная по запросу.
- Динамический список моделей с сервера (запрос списка через API).
- Отдельные токен-лимиты/температуры под модель; `max_tokens` и формула не меняются.

## Decisions

**D1 — модель как параметр `ask(..., model=...)`, состояние на `TabletopAITUI`.**
`self.model` на `TabletopAITUI` (как `self.settings`), дефолт параметра `ask()` — `config.DEFAULT_MODEL`. Альтернатива (модель как атрибут клиента, создаваемого с ней) отклонена: мутация клиента после создания — новый паттерн, а параметр консистентен с `temperature`/`max_tokens`. `/logictask` передаёт `model=self.model` в своём `_call` — прогон следует выбору.

**D2 — список моделей и дефолт в `core/config.py`.**
`AVAILABLE_MODELS: List[str]` + `DEFAULT_MODEL = AVAILABLE_MODELS[0]`; `MODEL_NAME` переименована (все использования обновляются). Альтернатива (список в `ui/models_screen.py`) отклонена — конфигурация живёт в `core/`, панели только читают.

**D3 — редьюсер `ui/models_screen.py` по образцу `commands_screen`.**
`ModelSelectionState(selected_index)` frozen-dataclass, `initial_state(current_model)` ставит курсор на текущую модель (как `initial_state(settings)` у `/settings`), `apply_key`: ↑/↓ — циклический сдвиг, Enter — `confirmed`, Esc — `cancelled`, остальное — без изменений. Текущая модель передаётся в рендер отдельным аргументом — пометка «текущая» (визуально: отметка у строки) не смешивается с курсором.

**D4 — строки в `COMMAND_OPTIONS`, не в `tui_app`.**
`("/models", "выбрать модель для ответов")` в `ui/commands_screen.py`; диспетчер `_handle_command` ловит `/models`. Автодополнение и панель `/commands` обновляются сами (единый источник).

**D5 — статус-бар: сегмент `Модель: <имя>`.**
В конец существующей строки статуса после температуры; пере-печатается существующим циклом после любой команды, отдельного подтверждения выбора не нужно.

**D6 — рефакторинг имён без алиасов совместимости.**
`DeepseekAPIClient` → `APIClient`, `DeepseekAPIError` → `APIError`; сообщения: «Неверный API-ключ.», «Ошибка API: …», «Ошибка соединения с API. …», «Превышено время ожидания ответа от API.», «Некорректный ответ от API.». Все импорты/тесты/README обновляются в том же изменении, внешних потребителей нет. Имя эндпоинта (OpenCode Zen) в имена не зашиваем — он переопределяется env. Слово `deepseek-v4-flash` в значении `DEFAULT_MODEL` остаётся.

## Risks / Trade-offs

- [Несуществующая модель в API → HTTP-ошибка] → существующий путь `DeepseekAPIError`→`APIError` показывает сообщение без traceback; список фиксирован, произвольный ввод в панель невозможен.
- [Другие модели не reasoning-модели / другой формат ответа] → клиент читает только `choices[0].message.content`; лишние поля (`reasoning_content`) игнорируются — совместимо по форме.
- [Кассеты записаны с `deepseek-v4-flash`] → кассеты не трогаем: e2e с кассетами не меняют модель, stub-серверу имя безразлично.
- [e2e-снапшоты: изменился статус-бар и панели] → прогнать `pytest --snapshot-update` после правок статуса, если снапшоты поедут.

## Migration Plan

Один репозиторий, без данных: ветка → TDD-коммиты → финальный `pytest` → `/opsx-archive` → merge в `main`. Откат — revert ветки.

## Open Questions

Нет — развилки D1/D2/D4 и отображение в статус-баре зафиксированы с пользователем.
