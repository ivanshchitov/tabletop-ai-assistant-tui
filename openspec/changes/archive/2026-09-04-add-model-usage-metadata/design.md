## Context

См. proposal.md - Why. Затрагивает четыре модуля: `core/config.py` (список моделей, цены),
`core/api_client.py` (HTTP-клиент), новый `core/usage.py` (расчёт стоимости), `ui/tui_app.py`
(вывод на экран после обычного вопроса и после каждого запроса `/logictask`). Требования — в
`specs/model-selection`, `specs/api-integration`, `specs/question-answering`,
`specs/prompt-strategies`.

## Goals / Non-Goals

**Goals:**
- Добавить `minimax-m2.5` и `kimi-k3` в список моделей без изменения поведения выбора модели.
- Дать клиенту способ вернуть метрики использования (время/токены/стоимость) вместе с ответом, не
  меняя поведение существующего способа получить только текст.
- Показать эти метрики на экране после ответа — как в обычном вопросе, так и после каждого
  отдельного запроса `/logictask`.

**Non-Goals:**
- Не сохранять метрики в `history.json` — они одноразовые, только для экрана в момент ответа.
- Не решать пиковое/непиковое ценообразование DeepSeek — берётся фиксированная база (off-peak),
  расхождение с реальным пиковым счётом — известное упрощение, не входит в эту фичу.
- Не менять UI `/models` (список остаётся плоским, без группировки по тиру слабая/средняя/сильная
  — эта группировка нужна только для сценария демонстрации дня 5, не для приложения).

## Decisions

- **Общий приватный метод запроса.** `APIClient` получает `_request(...)`, выполняющий HTTP-вызов
  с ретраями и обработкой ошибок (текущее тело `ask()` без разбора ответа) и возвращающий сырой
  JSON ответа плюс замеренное время. `ask()` достаёт из него `content`; новый `ask_with_usage()`
  дополнительно достаёт `usage` и считает стоимость. Альтернатива — дублировать HTTP-логику в двух
  методах — отклонена: ретраи/обработка ошибок продублировались бы и разошлись бы при будущих
  правках.
- **`AnswerMeta` — простой dataclass**, а не расширение возвращаемого типа `ask()`. Смена
  сигнатуры `ask()` задела бы `/logictask` и все существующие тесты/фейковые клиенты, которые
  ожидают строку. Раздельные методы держат старый контракт нетронутым.
- **Расчёт стоимости — в отдельном `core/usage.py`**, а не внутри `api_client.py`: стоимость — это
  чистая функция от `(model, prompt_tokens, completion_tokens)` и таблицы цен, отдельный модуль
  тестируется без HTTP-моков.
- **Цена — фиксированное число, а не диапазон.** Часть моделей (DeepSeek V4 Flash/Pro) имеет
  разные цены peak/off-peak на стороне OpenCode Zen. Хранится одно (off-peak, более низкое)
  значение на модель — время суток на клиенте не отслеживается, а цель дня 5 — сравнение порядка
  величины между слабой/средней/сильной моделью, не бухгалтерская точность.
- **Печать доп.-информации — рядом с существующим `_print_typing`**, отдельной вспомогательной
  функцией в `ui/tui_app.py`, вызываемой и из `_handle_question`, и из `_call` внутри
  `_run_strategy`. Так поведение (одна строка на каждый фактический вызов API) не дублируется
  в двух местах с риском разъехаться.
- **Заглушка `tests/e2e/stub_api.py` возвращает фиксированный `usage`** (не зависящий от длины
  вопроса) — этого достаточно, чтобы e2e-тесты проверили сам факт проброса метрик до экрана, не
  превращая тесты в проверку токенизации.

## Risks / Trade-offs

- [Цена off-peak расходится с реальным пиковым счётом] → некритично для цели дня (сравнение
  порядка величины между тирами моделей), явно задокументировано в `core/config.py` комментарием.
- [Новый метод `ask_with_usage` дублирует часть ответственности с `ask()`] → смягчено общим
  `_request()`: расхождение возможно только в постобработке (usage/cost), не в HTTP-логике.
- [Модель без цены в `MODEL_PRICING` (например, добавленная позже вручную)] → `estimate_cost`
  возвращает `None`, экран печатает пометку «неизвестно» вместо стоимости, не падает.
