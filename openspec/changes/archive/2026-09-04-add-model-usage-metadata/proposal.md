## Why

День 5 челленджа требует сравнить слабую, среднюю и сильную модель на одном и том же вопросе и
замерить время ответа, количество токенов и стоимость. Сейчас в проекте выбор модели уже есть
(`/models`), но список не покрывает три чётких тира по цене/силе, а после ответа пользователь не
видит ни времени, ни токенов, ни стоимости запроса — сравнение моделей приходится делать вслепую.

## What Changes

- В `AVAILABLE_MODELS` (`core/config.py`) добавляются `minimax-m2.5` и `kimi-k3` — вместе с уже
  существующими `deepseek-v4-flash` (слабая), `minimax-m2.5` (средняя) и `kimi-k3` (сильная)
  образуют явный слабый/средний/сильный тир для сравнения.
- Новый `MODEL_PRICING` в `core/config.py`: цена входных/выходных токенов (за 1M) для каждой
  модели из `AVAILABLE_MODELS`.
- Новый модуль `core/usage.py` с `estimate_cost(model, prompt_tokens, completion_tokens)` —
  считает стоимость запроса по `MODEL_PRICING`; для модели без цены в таблице возвращает `None`,
  а не падает.
- `APIClient` (`core/api_client.py`) получает новый метод `ask_with_usage(...)`, возвращающий
  структуру `AnswerMeta` (текст ответа, модель, время ответа, `prompt_tokens`, `completion_tokens`,
  `total_tokens`, стоимость). Существующий `ask()` не меняет поведение и продолжает возвращать
  только текст — оба метода используют общую внутреннюю логику запроса, чтобы не дублировать
  ретраи и обработку ошибок.
- После каждого ответа модели — как в обычном вопросе (`/handle_question`), так и в каждом
  отдельном запросе внутри `/logictask` (для всех четырёх стратегий, по одной строке на каждый
  фактический вызов API, не агрегатом) — на экран печатается строка с временем ответа,
  количеством токенов и стоимостью. Эта строка не сохраняется в `history.json` и не входит в
  постоянный лог диалогов — только вывод на экран в момент ответа.
- Тестовый stub-сервер (`tests/e2e/stub_api.py`) отдаёт поле `usage` в ответе, чтобы e2e-тесты
  могли проверить реальный проброс метрик от API до экрана.

### Modified Capabilities

- `model-selection`: список доступных моделей расширяется до явного слабого/среднего/сильного
  тира и получает таблицу цен для расчёта стоимости.
- `api-integration`: клиент API получает способ вернуть вместе с ответом метрики использования
  (время, токены, стоимость), не ломая существующий контракт `ask()`.
- `question-answering`: ответ на обычный вопрос сопровождается на экране строкой с временем,
  токенами и стоимостью запроса.
- `prompt-strategies`: каждый запрос внутри `/logictask` (по всем четырём стратегиям) тоже
  сопровождается на экране строкой с временем, токенами и стоимостью — отдельно на каждый вызов.

## Impact

- Код: `core/config.py`, `core/api_client.py`, `core/usage.py` (новый), `ui/tui_app.py`.
- Тесты: `tests/unit/test_config.py`, `tests/unit/test_api_client.py`, `tests/unit/test_usage.py`
  (новый), `tests/unit/test_tui_app.py`, `tests/e2e/stub_api.py`, `tests/e2e/test_models_flow.py`,
  `tests/e2e/test_strategies.py`; возможна правка `tests/e2e/snapshots/`.
- Внешние системы: не затрагивает — метрики приходят в стандартном поле `usage` ответа
  OpenAI-совместимого API OpenCode Zen, новых внешних вызовов не добавляется.
