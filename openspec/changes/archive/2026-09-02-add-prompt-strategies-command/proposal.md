## Why

Приложение всегда решает задачу одним способом — вопрос + форматные инструкции. Разные техники промптинга (прямой вопрос, пошаговое рассуждение, самогенерация промпта, панель экспертов) дают разное качество решения одной и той же задачи, но сравнить их в приложении сейчас негде. Нужен режим, который прогоняет одну фиксированную логическую задачу через модель четырьмя способами и показывает все ответы подряд — для наглядной демонстрации и сравнения техник.

## What Changes

- Новая команда `/logictask` в главном цикле TUI: **BREAKING** — при запуске открывает интерактивную панель выбора стратегии (↑/↓, Enter — запуск, Esc — отмена) и решает фиксированную настольно-игровую логическую задачу (переправа волка, козы и капусты, тематизированная под настольную игру) выбранной стратегией. Прогон всех стратегий подряд не предусмотрен.
- Четыре стратегии на выбор:
  1. **Прямой ответ** — задача отправляется с единственным жёстким условием: ответ должен содержать только ответ, без решения, без шагов и без выводов (форматные инструкции `AnswerSettings` не применяются).
  2. **Пошаговое решение** — в промпт добавляется инструкция «решай пошагово» (chain-of-thought).
  3. **Промпт от модели** — первый запрос просит модель составить промпт для решения задачи, второй запрос использует этот промпт.
  4. **Панель экспертов** — трое экспертов зафиксированы в приложении заранее (шеф-повар, психолог животных — специалист по взаимоотношениям животных между собой и с людьми, специалист по теории игр); решение получается от каждого отдельным запросом с собственным системным промптом-ролью.
- Каждая выбранная стратегия помечается в выводе заголовком (например, «Стратегия 2: пошаговое решение»), шаги стратегии 3 и 4 также помечаются, чтобы ответы было легко отличить в скроллбеке.
- Результаты НЕ записываются в историю (`history.json`) — это экспериментальный прогон, а не диалоговый обмен; счётчик диалогов в статус-баре не меняется.
- Настройки ответа (формат, объём, лимит списка) к прогонам `/logictask` НЕ применяются: запросы не содержат форматных инструкций, а технический потолок токенов фиксируется от значения объёма по умолчанию и не зависит от настроек сессии.
- Промпты всех стратегий собираются в `core/` (новый модуль), использование ответа одного шага как входа следующего выполняется на клиенте.
- Ошибка API во время выбранной стратегии НЕ прерывает сессию: печатается сообщение об ошибке, командой можно воспользоваться повторно.
- Выбор стратегии — интерактивная панель в стиле `/settings`: чистый редьюсер в `ui/` (testable без терминала), вокруг него цикл read-key/redraw в `ui/tui_app.py`. Панель описывает, какая задача будет решаться: текст фиксированной задачи печатается в журнал вместе с меню и присутствует в кадре панели.

## Capabilities

### New Capabilities
- `prompt-strategies`: решение одной фиксированной логической задачи четырьмя техниками промптинга (прямой ответ, пошагово, промпт-от-модели, панель экспертов), составление промптов каждой стратегии и правила сквозной передачи данных между запросами.

### Modified Capabilities
- `terminal-ui`: добавляется команда `/logictask` (**BREAKING**: вместо прогона всех стратегий — интерактивная панель выбора одной; распознавание по первому слову, автодополнение по Tab, продолжение сессии после ошибки); обновляется список команд в статус-баре.

## Impact

- `core/prompts.py` или новый модуль `core/strategies.py` — конструкторы промптов четырёх стратегий; фиксированный текст задачи; фиксированные роли трёх экспертов.
- `core/api_client.py` — без изменений: все запросы укладываются в существующий `ask(system_message, user_message)`.
- `ui/logictask_screen.py` (новый) — чистый редьюсер панели выбора стратегии; `ui/tui_app.py` — регистрация команды `/logictask`, цикл read-key/redraw вокруг панели, запуск выбранной стратегии, вывод заголовков и ответов в append-only журнал.
- `ui/tui_app.py` (`COMMANDS`) — список команд для автодополнения и статус-бара.
- Тесты: `tests/unit/test_strategies.py` (промпты стратегий), `tests/unit/test_logictask_screen.py` (редьюсер панели), `tests/unit/test_tui_app.py` (команда), `tests/e2e/` (панель выбора и прогон `/logictask` против stub API, проверка фактических запросов к модели), снимки экрана обновляются.
- Квота API: один вызов `/logictask` порождает столько запросов, сколько требует выбранная стратегия (прямой 1, пошаговый 1, промпт-от-модели 2, эксперты 3).
