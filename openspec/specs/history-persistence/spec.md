## Purpose

Сохранение диалогов между запусками в единственном файле `history.json`: загрузка и воспроизведение при старте, немедленное сохранение каждого успешного обмена, ограничение объёма и очистка командой `/clear`.

## Requirements

### Requirement: Расположение и переопределение пути
История SHALL храниться в файле `history.json` в корне репозитория. Путь SHALL переопределяться переменной окружения `TABLETOP_HISTORY_FILE` — так, чтобы путь по умолчанию выводился из расположения кода, а не из рабочего каталога процесса: ни один запуск (включая тестовые) не должен писать в реальный файл без явного переопределения.

#### Scenario: Переопределение пути
- **WHEN** задана переменная `TABLETOP_HISTORY_FILE`, указывающая на другой файл
- **THEN** история читается и пишется в указанный файл, а реальный `history.json` не трогается

### Requirement: Загрузка и воспроизведение при старте
История SHALL загружаться один раз при запуске. Если она непуста, прошлые обмены SHALL воспроизводиться в журнал главного экрана в исходном виде (вопрос, ответ, разделитель) до первого приглашения ввода; если пуста — показывается приветственное сообщение.

#### Scenario: Непустая история
- **WHEN** приложение запускается с сохранёнными диалогами
- **THEN** все сохранённые обмены видны в журнале, приветствие не показывается

#### Scenario: Пустая история
- **WHEN** приложение запускается впервые (файла истории нет)
- **THEN** показывается приветственное сообщение, а не пустой реплей

### Requirement: Немедленное сохранение каждого обмена
Каждый успешный обмен (вопрос и полученный ответ) SHALL добавляться в историю и сразу же записываться на диск — сбой приложения после ответа не должен терять историю. Неудачные запросы (ошибка API) SHALL NOT попадать в историю.

#### Scenario: Обмен сохранён
- **WHEN** модель ответила на вопрос
- **THEN** пара «вопрос–ответ» немедленно появляется в файле истории

#### Scenario: Ошибка API не сохраняется
- **WHEN** запрос к модели завершился ошибкой
- **THEN** файл истории не изменяется

### Requirement: Ограничение объёма истории
История SHALL хранить не более `HISTORY_LIMIT` последних записей — по умолчанию 50; значение
берётся из конфигурации и переопределяется переменной окружения `TABLETOP_HISTORY_LIMIT`.
Ограничение SHALL применяться и при добавлении (вытесняются старейшие записи), и при загрузке
файла с бо́льшим числом записей (остаются последние `HISTORY_LIMIT`).

#### Scenario: Вытеснение старейшей записи
- **WHEN** в историю, уже содержащую `HISTORY_LIMIT` записей, добавляется новая
- **THEN** в файле остаются `HISTORY_LIMIT` записей, старейшая вытеснена

#### Scenario: Обрезка при загрузке
- **WHEN** файл истории содержит более `HISTORY_LIMIT` записей
- **THEN** приложение загружает только последние `HISTORY_LIMIT`

#### Scenario: Лимит по умолчанию без переменной окружения
- **WHEN** `TABLETOP_HISTORY_LIMIT` не задана
- **THEN** лимит равен 50, прежнее поведение не меняется

### Requirement: Очистка командой /clear
Команда `/clear` SHALL очищать историю и в памяти, и в файле, о чём сообщается пользователю. Последующий запуск SHALL начинаться с пустой историей.

#### Scenario: Очистка
- **WHEN** пользователь выполняет `/clear` при непустой истории
- **THEN** файл истории становится пустым и выводится подтверждение

### Requirement: Устойчивость к повреждённому хранилищу
Отсутствующий файл, нечитаемый JSON или ошибка записи SHALL NOT приводить к падению приложения: битый файл читается как пустая история, ошибка записи игнорируется, работа продолжается.

#### Scenario: Битый файл истории
- **WHEN** `history.json` содержит невалидный JSON
- **THEN** приложение стартует с пустой историей, без ошибки

#### Scenario: Ошибка записи не фатальна
- **WHEN** запись истории на диск не удалась (например, каталог недоступен)
- **THEN** приложение продолжает работу, диалог не прерывается

### Requirement: Реплей истории восстанавливает контекст агента
Воспроизведение истории при старте SHALL засеивать стек сообщений агента: каждая пара «вопрос–ответ» из `history.json` SHALL превращаться в ход `user` (вопрос, пересобранный с активными настройками ответа) и ход `assistant` (ответ дословно). Первый вопрос после перезапуска с непустой историей SHALL отправляться модели вместе с восстановленными обменами, как если бы сессия не прерывалась. Потолок глубины контекста SHALL применяться к восстановленным ходам так же, как к ходам живой сессии.

#### Scenario: Первый вопрос после рестарта несёт прошлый обмен
- **WHEN** приложение перезапущено с непустой `history.json` (есть хотя бы один сохранённый обмен) и пользователь задаёт первый вопрос
- **THEN** запрос содержит system, восстановленный обмен (user и assistant) и новый user-ход

#### Scenario: Рестарт с пустой историей
- **WHEN** приложение запущено с пустой или отсутствующей историей
- **THEN** стек агента пуст и первый вопрос отправляется без ходов, как при первом запуске

#### Scenario: Очистка после рестарта
- **WHEN** после рестарта с непустой историей выполнена команда `/clear` и задан новый вопрос
- **THEN** файл истории пуст, стек агента пуст, запрос содержит system и один user-ход

### Requirement: Метрики использования в записях истории
Каждый успешно сохранённый обмен SHALL хранить метрики использования своего запроса:
входные, выходные и суммарные токены и стоимость (null, если стоимость не рассчитана).
Записи без метрик (старый формат файла) SHALL читаться как обычные обмены без метрик.
Итог расхода всей сохранённой истории SHALL вычисляться суммированием метрик по записям;
из-за вытеснения записей за лимит итог отражает расход удержанной истории. `/clear`
обнуляет эти итоги вместе с историей.

#### Scenario: Обмен сохраняется с метриками
- **WHEN** вопрос успешно отвечен моделью
- **THEN** запись истории содержит блок метрик с токенами и стоимостью этого запроса

#### Scenario: Файл старого формата читается
- **WHEN** в файле есть записи без блока метрик
- **THEN** они загружаются как обычные обмены, ошибок нет, итог расхода их не учитывает

#### Scenario: Вытесненная запись уносит расход
- **WHEN** запись вытеснена за лимит истории
- **THEN** её метрики больше не входят в итог расхода сохранённой истории
