## Purpose

Сохранение диалогов между запусками в единственном файле `history.json`: загрузка и воспроизведение при старте, немедленное сохранение каждого успешного обмена, ограничение объёма и очистка командой `/clear`.

## Requirements

### Requirement: Расположение и переопределение пути
История SHALL храниться в файле `history.json` в корне репозитория. Путь SHALL переопределяться переменной окружения `TABLETOP_HISTORY_FILE` — так, чтобы путь по умолчанию выводился из расположения кода, а не из рабочего каталога процесса: ни один запуск (включая тестовые) не должен писать в реальный файл без явного переопределения.

#### Scenario: Переопределение пути
- **WHEN** задана переменная `TABLETOP_HISTORY_FILE`, указывающая на другой файл
- **THEN** история читается и пишется в указанный файл, а реальный `history.json` не трогается

### Requirement: Загрузка и воспроизведение при старте
История SHALL загружаться один раз при запуске. Если она непуста, прошлые обмены SHALL воспроизводиться в журнал главного экрана в исходном виде (вопрос, ответ, разделитель) до первого приглашения ввода; если пуста — показывается приветственное сообщение.

#### Scenario: Непустая история
- **WHEN** приложение запускается с сохранёнными диалогами
- **THEN** все сохранённые обмены видны в журнале, приветствие не показывается

#### Scenario: Пустая история
- **WHEN** приложение запускается впервые (файла истории нет)
- **THEN** показывается приветственное сообщение, а не пустой реплей

### Requirement: Немедленное сохранение каждого обмена
Каждый успешный обмен (вопрос и полученный ответ) SHALL добавляться в историю и сразу же записываться на диск — сбой приложения после ответа не должен терять историю. Неудачные запросы (ошибка API) SHALL NOT попадать в историю.

#### Scenario: Обмен сохранён
- **WHEN** модель ответила на вопрос
- **THEN** пара «вопрос–ответ» немедленно появляется в файле истории

#### Scenario: Ошибка API не сохраняется
- **WHEN** запрос к модели завершился ошибкой
- **THEN** файл истории не изменяется

### Requirement: Ограничение объёма истории
История SHALL хранить не более 50 последних записей. Ограничение SHALL применяться и при добавлении (вытесняются старейшие записи), и при загрузке файла с бо́льшим числом записей (остаются последние 50).

#### Scenario: Вытеснение старейшей записи
- **WHEN** в историю, уже содержащую 50 записей, добавляется новая
- **THEN** в файле остаются 50 записей, старейшая вытеснена

#### Scenario: Обрезка при загрузке
- **WHEN** файл истории содержит более 50 записей
- **THEN** приложение загружает только последние 50

### Requirement: Очистка командой /clear
Команда `/clear` SHALL очищать историю и в памяти, и в файле, о чём сообщается пользователю. Последующий запуск SHALL начинаться с пустой историей.

#### Scenario: Очистка
- **WHEN** пользователь выполняет `/clear` при непустой истории
- **THEN** файл истории становится пустым и выводится подтверждение

### Requirement: Устойчивость к повреждённому хранилищу
Отсутствующий файл, нечитаемый JSON или ошибка записи SHALL NOT приводить к падению приложения: битый файл читается как пустая история, ошибка записи игнорируется, работа продолжается.

#### Scenario: Битый файл истории
- **WHEN** `history.json` содержит невалидный JSON
- **THEN** приложение стартует с пустой историей, без ошибки

#### Scenario: Ошибка записи не фатальна
- **WHEN** запись истории на диск не удалась (например, каталог недоступен)
- **THEN** приложение продолжает работу, диалог не прерывается
