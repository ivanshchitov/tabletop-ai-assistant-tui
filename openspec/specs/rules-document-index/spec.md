# rules-document-index Specification

## Purpose
Локально индексировать документы с правилами настольных игр, находить подтверждающие фрагменты для ответов и сравнивать стратегии разбиения текста.

## Requirements

### Requirement: Явная индексация корпуса правил
Приложение SHALL индексировать документы правил только по явной команде `/rules index`, SHALL извлекать из поддерживаемых PDF текст, SHALL создавать локально сохранённые эмбеддинги и SHALL хранить метаданные `source`, `title/file`, `section` и `chunk_id` для каждого чанка. Корпус SHALL содержать не менее 20 страниц текста и материалы 2–3 настольных игр. Запуск приложения SHALL NOT запускать индексацию.

#### Scenario: Индексация по команде
- **WHEN** пользователь вводит `/rules index`
- **THEN** документы из `docs/rules/` индексируются, показывается итог по файлам и чанкам, а индекс сохраняется локально

#### Scenario: Приложение запускается без индексации
- **WHEN** приложение запускается с документами, но без готового индекса
- **THEN** приложение запускается без чтения документов и без создания индекса

#### Scenario: Нет документов или ошибка чтения
- **WHEN** пользователь запускает `/rules index`, но корпус пуст или PDF не удаётся прочитать
- **THEN** выводится понятная причина, приложение продолжает работу, а частичный индекс не выдаётся за готовый

### Requirement: Стратегии разбиения и сравнение
Индексация SHALL поддерживать разбиение по фиксированному размеру и по структуре документа. Структурный способ SHALL учитывать заголовки, разделы или границы файлов. Приложение SHALL сравнивать обе стратегии на одном запросе и показывать количество и размеры чанков и найденные фрагменты с источниками.

#### Scenario: Сравнить стратегии
- **WHEN** пользователь вводит `/rules compare <запрос>`
- **THEN** приложение показывает результаты поиска по обоим разбиениям для одного запроса и различия в чанках

#### Scenario: Документ без заголовков
- **WHEN** структурная стратегия обрабатывает документ без распознанных заголовков
- **THEN** документ разбивается по границам файла и пределу размера, без потери текста

### Requirement: Поиск фрагментов для ответа
Когда индекс готов и включён режим RAG, вопрос пользователя о правилах настольной игры SHALL сопровождаться наиболее релевантными фрагментами из индекса. После ответа приложение SHALL показывать название документа, раздел и идентификатор найденного чанка. В режиме без RAG приложение SHALL NOT искать фрагменты, добавлять их в запрос модели или приписывать ответу источники. Если индекс отсутствует или подходящих фрагментов нет, SHALL сохраняться обычное поведение ответа.

#### Scenario: Ответ содержит подтверждающие источники
- **WHEN** пользователь задаёт вопрос, ответ на который поддерживают документы готового индекса, и режим RAG включён
- **THEN** модель получает найденные фрагменты, а под ответом видны их названия, разделы и идентификаторы

#### Scenario: Вопрос без подходящего фрагмента
- **WHEN** индекс готов, но поиск не находит фрагмент выше порога релевантности
- **THEN** вопрос обрабатывается обычным путём, и приложение не приписывает ответ источникам

#### Scenario: Индекс не создан
- **WHEN** пользователь задаёт вопрос до первой индексации
- **THEN** вопрос обрабатывается обычным путём, а команда `/rules index` доступна для последующего построения индекса

#### Scenario: Режим без RAG
- **WHEN** пользователь отключил RAG и задаёт вопрос по правилам
- **THEN** вопрос отправляется модели без поиска и фрагментов индекса, а источники под ответом не показываются

### Requirement: Команды индекса правил
Команда `/rules` SHALL показывать состояние индекса, состояние режима RAG и доступные подкоманды. `/rules index` SHALL создавать индекс; `/rules compare <запрос>` SHALL сравнивать стратегии без изменения сохранённого индекса; `/rules mode on|off` SHALL переключать использование индекса для следующих вопросов в текущей сессии. При запуске нового сеанса режим RAG SHALL быть включён. Эти команды SHALL NOT отправлять запрос модели и SHALL NOT попадать в историю диалога.

#### Scenario: Справка команды
- **WHEN** пользователь вводит `/rules` без подкоманды
- **THEN** приложение показывает состояние индекса, состояние режима RAG и синтаксис доступных команд

#### Scenario: Команды не используют API модели
- **WHEN** пользователь запускает `/rules index` или `/rules compare <запрос>`
- **THEN** ни одного запроса к модели не выполняется

#### Scenario: Переключить режим
- **WHEN** пользователь вводит `/rules mode off` или `/rules mode on`
- **THEN** приложение подтверждает выбранный режим для следующих вопросов без обращения к модели

#### Scenario: Неверный режим
- **WHEN** пользователь вводит `/rules mode` без `on|off` или с иным значением
- **THEN** приложение показывает правильный синтаксис и сохраняет текущий режим
